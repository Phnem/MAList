# TICKET-04: Плеер — замороженный размытый кадр и катана вместо текста загрузки

## Status

DONE

## Objective

При переключении серии и обновлении ссылки на поток показывать катану поверх замороженного
размытого кадра вместо текста «Загружаем серию N…» / «Обновляем ссылку на поток…».

## User or system value

Главный пункт запроса: переход между сериями перестаёт быть строкой текста.

## Dependencies

TICKET-03.

## Scope

- Снимок кадра `PixelCopy` с `SurfaceView` плеера в момент входа в загрузку, даунскейл и блюр
  по bitmap (работает на всех API, в отличие от `Modifier.blur`).
- Снимок не делается при DRM-потоке и в PiP; при неудаче — только затемнение.
- `StreamPlayerSurface`: новый параметр `loading: Boolean = false`; поверхность владеет снимком
  и показывает оверлей (у неё уже есть и `SurfaceView`, и признак DRM).
- `StreamPlayerActivity`: `busyText` для загрузки удаляется, вместо него передаётся
  `loading = switchingTo != null || retrying`. Блок ошибок и его кнопки остаются.

## Out of scope

- Буферизация посреди воспроизведения (`isBuffering`) — не трогать.
- Локальный плеер (`LocalPlayerActivity`, `PlayerScreen`) — не трогать.

## Acceptance criteria

- [ ] При переключении серии виден размытый замороженный кадр и катана; текста нет.
- [ ] То же при обновлении ссылки на поток.
- [ ] Ошибка переключения по-прежнему показывает текст и кнопки «Повторить»/«Закрыть».
- [ ] На DRM-потоке и в PiP снимок не запрашивается; загрузка показывается на затемнении.
- [ ] Неудачный снимок не роняет и не подвешивает экран.
- [ ] Спиннер буферизации в `PlayerControls` не изменён; локальный плеер работает как раньше.
- [ ] Bitmap снимка освобождается при скрытии оверлея — снимок не удерживается всю сессию.
- [ ] `./gradlew :app:assembleDebug` и `./gradlew :app:testDebugUnitTest` проходят.

- Ручная проверка на устройстве (пользователь): переключение серии кнопкой «дальше»,

## Expected architecture impact

`StreamPlayerSurface` получает +1 параметр. Снимок кадра — отдельный маленький файл, а не
довесок к `AmbientDock` (у того другая задача: полосы и средний цвет).

## Risks

- `PlayerControls` общий с локальным плеером — правка не должна его касаться вовсе.
- Снимок в момент старта переключения может прийти пустым, если сюрфейс ещё не отрисован —
  обрабатывать как неудачу и падать в затемнение.
- Держать полноразмерный bitmap дорого: снимать уменьшенным.

## Implementation notes

Новый `media/ui/FrozenFrame.kt` — `rememberFrozenFrame(active, enabled, surfaceProvider)`.

- **Блюра как отдельного шага нет.** Снимок берётся шириной 128 px и растягивается на весь
  экран; билинейная фильтрация при таком увеличении и есть размытие. Это дешевле собственного
  box-blur, работает на всех API и не заводит копию алгоритма рядом с уже существующим в
  `AmbientDock` (там он нужен для полос дока и живёт внутри его сэмплера).
- **Снимок делается один раз на вход в ожидание.** При переключении серии кадр обязан замереть.
- Высота снимка берётся из пропорций сюрфейса — иначе `PixelCopy` сплющит картинку.
- Неудача снимка — штатный исход, а не ошибка: DRM (secure surface пикселей не отдаёт), PiP,
  ещё не отрисованный сюрфейс. Возвращается `null`, вызывающая сторона показывает одно затемнение.
- Снимок держится ещё 450 мс после конца ожидания — дольше, чем длится уход оверлея, иначе кадр
  исчезал бы раньше катаны. Затем ссылка отпускается; `recycle()` не вызывается намеренно —
  битмап может быть ещё в отрисовке, а 128×72 не тот размер, ради которого стоит рисковать.

`StreamPlayerSurface`: параметр `loading`. Поверхность сама снимает кадр и накрывает его
оверлеем — у неё уже есть и `SurfaceView`, и признак DRM. Кадр гаснет через `alpha` у `Image`, а
не через `AnimatedVisibility`: снимок может появиться на кадр позже флага, и обёртка входила бы
в композицию уже видимой.

`StreamPlayerActivity`: `busyText` удалён целиком, вместо него
`loading = switchingTo != null || retrying`. Блок ошибок остался, из него ушла ветка
«кнопки только когда не идёт загрузка» — теперь блок и показывается только для ошибок.

## Review findings

Самопроверка диффа:

- `PlayerControls` не тронут; локальный плеер (`LocalPlayerActivity`, `PlayerScreen`,
  `DownloadedPlayerActivity`) не тронут. Затронуты только три файла `media/ui/`. ✓
- Спиннер буферизации (`PlayerControls:541`) на месте — ожидание посреди воспроизведения
  осталось прежним. ✓
- Тексты ошибок и обе кнопки сохранены, поведение «закрыть ошибку переключения» не изменилось. ✓
- Снимок не удерживается всю сессию: ссылка отпускается через 450 мс после конца ожидания. ✓
- `IllegalArgumentException` от `PixelCopy` (сюрфейс исчез между проверкой и запросом) поймано —
  как в существующем сэмплере доков. ✓
- Длительности взяты из `MotionTokens.ScrimFadeMillis`; вторая (уход) вынесена в именованную
  константу рядом с пояснением, а не вписана числом в вызов. ✓
- BLOCKING-замечаний нет.

Замечание уровня `OPTIONAL`, не исправлялось: при включённом режиме «заполнить кадр» (`CROP`)
видео масштабируется `graphicsLayer`, а снимок берётся из буфера сюрфейса без этого масштаба.
Расхождение неразличимо под размытым кадром и затемнением 0.82, а тащить сюда состояние
масштаба — лишняя связность.
