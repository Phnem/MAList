## Verification commands

### Fast checks

```
.\gradlew.bat :app:compileDebugKotlin
```

**Только `gradlew.bat` через PowerShell.** `./gradlew` в git bash падает с `bad interpreter`
(шебанг с CRLF) — и падает молча, если пайпить в `tail`.

### Ticket checks

```
.\gradlew.bat :app:testDebugUnitTest
```

Обязателен для TICKET-02, TICKET-03, TICKET-04, TICKET-07.

### Full checks

```
.\gradlew.bat :app:assembleDebug
```

Перед финальным ревью.

**Известное падение набора:** `StatsRatingBucketTest.buckets_continuous_noGaps` — существовавший
дефект, не регрессия (`vetro-player` TICKET-05). Полный набор зелёным считать нельзя.

**Чего проверить нельзя.** Жесты, реальное воспроизведение, совпадение с макетом на глаз, «чутка
прозрачным», плавность анимации, поведение на устройстве — подтверждает пользователь. Устройства и
эмулятора в сессии нет; эти проверки не будут отмечены пройденными.

## Known risks

1. **TICKET-04 необратимо пишет данные пользователя.** Ошибка в границе прочитанного проставит
   `read` непрочитанным главам без способа откатить. Самый опасный тикет пакета.
2. **TICKET-02 задевает оба плеера через общий `PlayerControls`.** Локальный плеер пользователь не
   просил трогать — он обязан сохранить прежнее поведение.
3. **TICKET-06 правит два чужих экрана** (настройки, меню серий) ради выноса градиента в токен.
   Любое отклонение значений — регрессия там, где ничего не просили.
4. **TICKET-05 может сделать список глав жадным.** Группа без томов содержит сотни глав и обязана
   остаться ленивой.
5. Три пункта из семи — визуальные и субъективные (1, 5, частично 4). Вероятны итерации по
   просмотру пользователем; это нормальный исход, а не провал.
6. Два пункта отменяют решения прошлых прогонов (D-2 → `vetro-todo` TICKET-03, D-5 →
   `vetro-player` D-2). Сами прошлые планы не переписываются: отмена фиксируется здесь.
