# TICKET-03: Автопереход на следующую серию

## Status

DONE_WITH_DEVIATIONS

## Objective

Конец серии переключает плеер на следующую — тем же путём, что кнопка «дальше». В обоих плеерах,
с переключателем в настройках. Пункт 2 списка, FR-2.

## User or system value

Досмотр серии перестаёт требовать действия. Пользователь сам предложил «имитацию нажатия кнопки
дальше» — значит, автопереход обязан идти через тот же вход, что кнопка, и не расходиться с ней в
поведении.

## Dependencies

TICKET-02 (общие файлы плееров).

## Scope

- `media/ui/StreamPlayerActivity.kt` — в существующей ветке `STATE_ENDED` после дописывания
  прогресса вызывается тот же `switchToEpisode(EpisodeRange.nextOf(...))`, что и кнопка.
- `localplayer/ui/PlayerScreen.kt` — переход на следующий файл списка по завершении, тем же входом,
  что кнопка «дальше».
- `ui/settings/SettingsUiState.kt`, `SettingsViewModel.kt`, `SettingsScreen.kt` — переключатель
  рядом с автопропуском заставок.
- `utils/…PlayerSettingsStrings` — подпись и пояснение переключателя (**не `UiStrings`**).
- `localplayer/ui/LocalPlayerViewModel.kt` — ключ настройки рядом с `AUTO_SKIP_KEY`.

## Out of scope

- Предзагрузка следующей серии (отклонена на интервью прошлого прогона).
- Автопереход между сезонами.
- Обратный отсчёт/плашка «следующая серия через N секунд».

## Acceptance criteria

- [x] По завершении серии (`STATE_ENDED` при известной длительности) плеер переключается на
      следующую — вызовом того же `switchToEpisode`, что и кнопка «дальше».
- [x] Работает в стриминговом и локальном плеере (в локальном — через `pauseAtEndOfMediaItems`,
      см. «Deviations»).
- [x] Переключатель в настройках включает и выключает поведение; по умолчанию **включено**
      (отсутствие ключа = `true` у всех четырёх читателей).
- [x] Выключенный переключатель возвращает прежнее поведение: в стриминге остаётся только запись
      прогресса, в локальном плеер останавливается на последнем кадре серии.
- [x] Последняя серия диапазона: `EpisodeRange.hasNext` = false → автопереход молчит.
- [x] Неудачный резолв идёт по тому же коду, что ручной: сообщение, серия играет дальше, повторов
      нет — отдельной ветки не появилось.
- [x] Прогресс завершившейся серии дописывается до подмены (существующий код не тронут, автопереход
      стоит после него).
- [x] Повторный `STATE_ENDED` во время резолва отсекается условием `switching`.
- [x] `UiStrings` не вырос: строки легли в `PlayerSettingsStrings`.

## Expected architecture impact

Минимальный: новый читатель у существующих `switchToEpisode` / `EpisodeRange` и одна настройка.
Единственный риск для архитектуры — соблазн продублировать логику перехода отдельно для автоматики.

## Risks

- `STATE_ENDED` приходит и в других обстоятельствах (пустой источник, ошибка потока) — переключаться
  только при известной длительности, как уже сделано для записи прогресса.
- Гонка с ручным нажатием: если `switchingTo != null`, автопереход обязан промолчать.
- В локальном плеере ExoPlayer уже сам идёт по плейлисту — проверить, что не получится двойного
  перехода через серию.
- Опечатка в ключе настройки оставит переключатель мёртвым, но внешне рабочим (тот же риск, что был
  у автопропуска).

## Implementation notes

Условие запуска — чистая функция `media/episode/AutoAdvance.kt`: `enabled && durationMs > 0 &&
hasNext && !switching`. Проверка длительности не косметическая: `STATE_ENDED` прилетает и от
пустого или сорвавшегося источника, и без неё автопереход утаскивал бы вперёд на каждой ошибке.

Ключ `AUTO_NEXT_KEY` заведён рядом с `AUTO_SKIP_KEY` в `LocalPlayerViewModel` и берётся оттуда
всеми читателями (`SettingsViewModel`, `StreamPlayerActivity`, `DownloadedPlayerActivity`,
`LocalPlayerViewModel`) — разъехавшееся имя оставило бы настройку внешне рабочей и мёртвой.

Дефолт `true` продублирован в каждом читателе как `?: true`. Это сознательно: у DataStore нет
общего места для дефолтов, и «отсутствует ключ» обязано читаться одинаково везде.

## Deviations

- **Планировалось:** в локальном плеере переключаться на следующий файл «тем же входом, что кнопка
  дальше».
  **Сделано:** настройка гасит уже существующий переход ExoPlayer через `pauseAtEndOfMediaItems`.
  **Причина:** у локального плеера серии лежат плейлистом, и переход по концу — его штатное
  поведение, которое работало и до этой правки. Добавить поверх собственный переход означало бы два
  независимых механизма на одно действие и риск перепрыгнуть серию.
  **Последствие:** в локальном плеере автопереход не «добавлен», а стал управляемым. Внешне
  требование выполнено: настройка включает и выключает поведение.
  **Follow-up:** не нужен.

  Соблазн продублировать логику перехода отдельно для автоматики (главный риск тикета) не
  реализован.
