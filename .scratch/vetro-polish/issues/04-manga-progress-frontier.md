# TICKET-04: Прогресс манги по границе прочитанного

## Status

PENDING

## Objective

Прогресс тайтла — длина прочитанного отрезка оглавления, а не число отметок: прочитана 16-я из 92 →
«16 / 92». При открытии вкладки «Главы» отметки проставляются задним числом всем главам до границы.
Пункт 3 списка, FR-3.

## User or system value

Сейчас карточка врёт: у человека, прочитавшего 16 глав подряд, показано «1 / 92». Пункт про
корректность данных, а не про оформление.

## Dependencies

Нет. Блокирует TICKET-05 и TICKET-06 (общий файл `MangaChaptersPage.kt`) и TICKET-07 (общий
`MangaReadingStore.kt`).

## Scope

- `manga/domain/MangaReadingSummary.kt` — правило счёта: `readChapters` = позиция самой дальней
  прочитанной главы в оглавлении (1-based), а не размер пересечения множеств.
- `manga/domain/` — новая чистая функция «ключи глав до границы, у которых нет отметки» для FR-3c.
- `manga/ui/MangaChaptersPage.kt` / соответствующая ViewModel — вызов проставления отметок при
  открытии вкладки.
- `manga/data/MangaReadingStore.kt` — пакетная запись отметок (одним обновлением снимка, не по
  главе за раз).
- `app/src/test/.../MangaReadingSummaryTest.kt` — расширение существующих 10 тестов.

## Out of scope

- Изменение формата снимка в DataStore.
- Автоматическое снятие отметок (необратимость принята пользователем, D-4).
- Фоновое обновление оглавлений — это `vetro-todo` TICKET-11, не входит.

## Acceptance criteria

- [ ] Прочитана только 16-я глава из 92 → `readChapters == 16`, доля 16/92.
- [ ] Граница считается по позиции в оглавлении (порядок списка источника), а не по дате чтения и
      не по номеру в ключе.
- [ ] Прочитана последняя глава → `readChapters == totalChapters`.
- [ ] Пустое оглавление → прежнее поведение: `totalChapters == null`, знаменатель не рисуется,
      отметки задним числом не проставляются.
- [ ] Отметок нет вовсе → `readChapters == 0`, `hasProgress == false`.
- [ ] Отметки на главы, которых нет в текущем оглавлении (смена источника/языка), границу не
      сдвигают и счётчик за знаменатель не выводят.
- [ ] Открытие вкладки «Главы» проставляет `read` всем главам до границы; в UI они помечены
      прочитанными.
- [ ] Повторное открытие вкладки ничего не переписывает (нечего проставлять — записи в DataStore
      нет).
- [ ] Карточка главного экрана и вкладка «Главы» считают по одной и той же функции — числа не
      расходятся.
- [ ] Новые главы считаются по прежнему правилу (вышли позже последнего чтения и не прочитаны).
- [ ] Тесты покрывают: середину, первую, последнюю, пустое оглавление, дырки в отметках, чужие
      ключи.

## Expected architecture impact

Доменное понятие уточняется: прогресс манги — граница, а не множество. Функция остаётся чистой и
единственным местом правила; UI ничего не считает сам.

## Risks

- **Необратимость.** Ошибка в границе проставит `read` главам, которых человек не читал, и снять их
  скопом будет нечем. Тесты на границу — до реализации, не после.
- «Позиция в оглавлении» зависит от порядка, в котором источник отдал главы. Если список приходит не
  отсортированным, граница уедет. Проверить, как `MangaChaptersPage` уже сортирует, и считать по
  тому же порядку.
- Смена языка перевода меняет состав оглавления (`chaptersForLanguage`) — граница считается по уже
  суженному списку, иначе числа разойдутся с показанным списком.
- Массовая запись отметок в DataStore при открытии вкладки не должна дёргать снимок по разу на
  главу.
