# TICKET-04: Прогресс манги по границе прочитанного

## Status

DONE

## Objective

Прогресс тайтла — длина прочитанного отрезка оглавления, а не число отметок: прочитана 16-я из 92 →
«16 / 92». При открытии вкладки «Главы» отметки проставляются задним числом всем главам до границы.
Пункт 3 списка, FR-3.

## User or system value

Сейчас карточка врёт: у человека, прочитавшего 16 глав подряд, показано «1 / 92». Пункт про
корректность данных, а не про оформление.

## Dependencies

Нет. Блокирует TICKET-05 и TICKET-06 (общий файл `MangaChaptersPage.kt`) и TICKET-07 (общий
`MangaReadingStore.kt`).

## Scope

- `manga/domain/MangaReadingSummary.kt` — правило счёта: `readChapters` = позиция самой дальней
  прочитанной главы в оглавлении (1-based), а не размер пересечения множеств.
- `manga/domain/` — новая чистая функция «ключи глав до границы, у которых нет отметки» для FR-3c.
- `manga/ui/MangaChaptersPage.kt` / соответствующая ViewModel — вызов проставления отметок при
  открытии вкладки.
- `manga/data/MangaReadingStore.kt` — пакетная запись отметок (одним обновлением снимка, не по
  главе за раз).
- `app/src/test/.../MangaReadingSummaryTest.kt` — расширение существующих 10 тестов.

## Out of scope

- Изменение формата снимка в DataStore.
- Автоматическое снятие отметок (необратимость принята пользователем, D-4).
- Фоновое обновление оглавлений — это `vetro-todo` TICKET-11, не входит.

## Acceptance criteria

- [x] Прочитана только 16-я глава из 92 → `readChapters == 16`, доля 16/92.
- [x] Граница считается по **номеру** главы (см. «Deviations»), а не по дате чтения и не по номеру
      в ключе; тест на независимость от порядка списка есть.
- [x] Прочитана последняя глава → `readChapters == totalChapters`, доля 1.0.
- [x] Пустое оглавление → `totalChapters == null`, знаменатель не рисуется, `chaptersToMarkRead`
      возвращает пустоту.
- [x] Отметок нет вовсе → `readChapters == 0`, `hasProgress == false`.
- [x] Отметки на главы вне текущего оглавления границу не сдвигают: она берётся только из глав
      самого оглавления.
- [x] Открытие вкладки «Главы» дописывает `read` главам до границы — через `markReadBulk` из
      наблюдателя прогресса.
- [x] Повторное открытие ничего не переписывает: `chaptersToMarkRead` возвращает пустой список, а
      `markReadBulk` на пустом списке выходит сразу.
- [x] Карточка и вкладка считают по одной функции `summarizeMangaReading` над одним и тем же
      списком (`chaptersForLanguage`).
- [x] Новые главы считаются по прежнему правилу; метка не гаснет — время дописанных отметок берётся
      от последнего чтения тайтла, а не текущее.
- [x] Тесты: середина, первая, последняя, дробные номера, дырки в отметках, чужие ключи, пустое
      оглавление, экстры без номера, независимость от порядка, идемпотентность дописывания.

## TDD classification

## Expected architecture impact

Доменное понятие уточняется: прогресс манги — граница, а не множество. Функция остаётся чистой и
единственным местом правила; UI ничего не считает сам.

## Risks

- **Необратимость.** Ошибка в границе проставит `read` главам, которых человек не читал, и снять их
  скопом будет нечем. Тесты на границу — до реализации, не после.
- «Позиция в оглавлении» зависит от порядка, в котором источник отдал главы. Если список приходит не
  отсортированным, граница уедет. Проверить, как `MangaChaptersPage` уже сортирует, и считать по
  тому же порядку.
- Смена языка перевода меняет состав оглавления (`chaptersForLanguage`) — граница считается по уже
  суженному списку, иначе числа разойдутся с показанным списком.
- Массовая запись отметок в DataStore при открытии вкладки не должна дёргать снимок по разу на
  главу.

## Implementation notes

Граница вынесена приватной функцией `readingFrontier` и переиспользована обоими выходами:
`summarizeMangaReading` (счёт) и `chaptersToMarkRead` (что дописать). Одно правило — одно место.

Дописывание отметок висит на наблюдателе прогресса в `MangaLibraryViewModel`, а не на разовом
событии открытия: оно само себя останавливает (после записи поток отдаёт полный прогресс, и чинить
становится нечего) и заодно срабатывает при смене языка перевода, где состав оглавления меняется.

`markReadBulk` пишет одним обновлением снимка. Цикл по `setRead` на тайтле в 92 главы дал бы
сотню записей в DataStore подряд, каждую со своей сериализацией и своим пробуждением коллектора.

## Deviations

- **Планировалось:** граница = позиция самой дальней прочитанной главы **в оглавлении**.
  **Сделано:** граница = **номер** самой дальней прочитанной главы.
  **Причина:** позиция завязана на порядок, в котором список отдал источник. Сегодня он
  восходящий (`sortedForReading` в `MangaSourceEngine`), но это невидимая связь: перевёрнутый
  список молча дал бы «прочитано 77 из 92» вместо 16. Формулировка пользователя тоже про номер
  главы, а не про позицию.
  **Последствие:** главы без номера (пролог, экстра) в отрезок не входят и считаются только по
  собственной отметке. Записано отдельным тестом.
  **Follow-up:** не нужен.

## Review findings

- **Найдено при реализации и исправлено до коммита:** первая версия `markReadBulk` ставила
  дописанным отметкам текущее время. Это сдвинуло бы «последнее чтение» тайтла на сейчас, а признак
  «вышли новые главы» считается именно по нему — метка погасла бы у всей коллекции при первом же
  открытии вкладки. Время берётся от последнего чтения тайтла.
- **Спека.** FR-3a…FR-3e выполнены.
- **Необратимость.** Дописываются только главы строго до границы и только те, у которых отметки
  нет; существующие записи (страница, время) не затираются.
- **Регрессии.** Все 10 прежних тестов остались зелёными без правок смысла — переименован один
  (`partially_read_title_…`), потому что его название описывало старое правило.
- **Архитектура (наблюдатель).** Доменное понятие уточнилось: прогресс манги — граница, а не
  множество отметок. UI ничего не считает сам, оба выхода идут через домен.

Блокирующих нет.
