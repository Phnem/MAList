# TICKET-07: Порядок раскладок ридера и вертикальный дефолт

## Status

DONE

## Objective

Кнопка раскладки ходит по циклу вертикальный свайп → вправо (LTR) → влево (RTL) → вертикальный;
новый тайтл открывается вертикальным; автоопределение режима по пропорциям убирается.
Пункт 7 списка, FR-7.

## User or system value

Пользователь читает вертикальным свайпом и хочет получать его сразу, а переключаться — в понятном
порядке. Автодетект сегодня решает за него и иногда решает не так.

## Dependencies

TICKET-04 (общий файл `MangaReadingStore.kt`).

## Scope

- `manga/ui/ReaderDock.kt` — `nextLayout` переезжает из приватной функции UI в тестируемую чистую
  функцию с новым порядком; иконка и подпись следуют за ней.
- `manga/data/MangaReadingStore.kt` — дефолт режима становится `Webtoon`.
- `manga/ui/MangaReaderViewModel.kt` — вызов автодетекта удаляется.
- `manga/domain/DetectReaderMode.kt` и его регистрация в `di/appModule.kt` — удаляются целиком
  (класс без вызывающих — мусор, см. архобзор §5).
- Тест на цикл раскладок.

## Out of scope

- Дефолт направления страниц (`PageDirection`) для тайтлов, где он уже выбран.
- Перенос настройки раскладки в глобальные настройки — она остаётся per-title.
- Оформление самой кнопки и дока.

## Expected architecture impact

Правило порядка выходит из UI-файла в тестируемую функцию. Удаление `DetectReaderMode` убирает
целый узел (сеть + анализ картинок + koin-регистрация), который больше никем не используется.

## Risks

- Смена дефолта затрагивает тайтлы, читавшиеся раньше без явного выбора: они перейдут на
  вертикальный. Ожидаемое следствие FR-7b, но проверить, что легаси-ключ не переопределяет дефолт
  в обратную сторону.
- `DetectReaderMode` тянет зависимость `client` в koin — удалять аккуратно, чтобы не уронить граф.
- `MangaReaderScreen` перестраивает страницы по `key(chapter, mode, direction)` — смена порядка
  цикла не должна ломать восстановление текущей страницы при переключении.

## Implementation notes

`nextLayout` уехала из `ReaderDock.kt` в `manga/domain/ReaderLayout.kt` как `nextReaderLayout`.
Выбор иконки и подписи остался в доке: это отрисовка, а не правило.

Стартовое значение `readerMode` (`stateIn(..., MangaReaderMode.Paged)`) тоже переведено на
`Webtoon`. Разойдись оно с дефолтом хранилища — ридер моргал бы постраничным режимом на открытии.

`legacyMode` теперь распознаёт `Paged` явно, а всё остальное (включая отсутствие ключа) читает как
`Webtoon`: раньше логика была зеркальной.

## Deviations

Нет. Удаление `hasExplicitMode` тикетом прямо не предусматривалось, но это единственный читатель
удалённого автодетекта — метод осиротел вместе с ним.

## Review findings

- **Спека.** FR-7a…FR-7e выполнены.
- **Совместимость.** Тайтлы с явным выбором не трогаются. Тайтлы без выбора, ранее работавшие как
  `Paged` по умолчанию, перейдут на вертикальный — это и заказано (D-7).
- **Граф koin** не сломан: `DetectReaderMode` был единственным потребителем своей регистрации,
  зависимость `client` используется другими компонентами.
- **Архитектура (наблюдатель).** Удалён целый мёртвый узел (сеть + анализ картинок + регистрация),
  правило порядка стало тестируемым.

Блокирующих нет.
