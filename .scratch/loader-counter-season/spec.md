# Индикатор загрузки, счётчик серий на карточке, сезон в Kodik

## Problem

Три независимых дефекта, заявленных пользователем 2026-08-02.

1. **Индикатор загрузки виден только вместе с доками.** Пока резолвится ссылка или
   переключается серия, экран выглядит зависшим: анимация появляется только по тапу и исчезает
   вместе с автоскрытием доков через 3.5 с. В режиме «картинка в картинке» индикатора нет вовсе.
2. **На карточке главного экрана бывает «15 / 12».** Числитель и знаменатель считаются в разных
   шкалах, поэтому просмотрено может превысить «всего».
3. **Вместо 2 сезона играет 1-й.** Пользователь смотрел S1E11, открыл S2E1 — заиграла S1E1;
   открыл S2E2 — заиграла S1E2. Источник — Kodik.

## Current behavior

### 1. Индикатор загрузки

`StreamPlayerActivity.kt:585` считает `loading = switchingTo != null || retrying` — верхнеуровнево
и корректно. `StreamPlayerSurface.kt:76` совмещает его с буферизацией плеера в `showLoading`
(`shouldShowStreamLoading`, уже покрыт `StreamLoadingVisibilityTest`).

Дальше значение теряется дважды:

- `StreamPlayerSurface.kt:245` передаёт `showLoading` как `isBuffering` **только** внутрь
  `PlayerControlsOverlay`, а весь этот вызов обёрнут в `if (!isInPip)` (строка 233). В PiP
  Compose-слой управления не композится целиком — вместе с индикатором.
- `localplayer/ui/PlayerControls.kt:531-558`: `BubbleClusterLoader` нарисован внутри того же
  `AnimatedVisibility(visible = controlsVisible)`, что и ряд prev/play-pause/next. То есть
  индикатор буквально вложен в анимацию скрытия доков и гаснет вместе с ними.

`controlsVisible` автоскрывается через 3500 мс (`PlayerControls.kt:200-205`) и переключается
тапом (строки 223-243).

### 2. Счётчик серий

- **X (числитель)** — `HomeViewModel.watchedEpisodes` (строки 78-99): сквозная нумерация по
  франшизе, `сумма серий сезонов до текущего + номер текущей серии`. Разбивка берётся из
  `SeasonEpisodesStore`.
- **Y (знаменатель)** — `HomeScreen.kt:648` передаёт `totalEpisodes = anime.episodes`. Это плоское
  поле одного сезона (`data/models/Anime.kt:13`), которое пишется только вручную в `AddEditViewModel`
  либо при явном «принять обновление» в `HomeViewModel.acceptUpdate()`.

Две разные шкалы. Для второго сезона из 12 серий, когда первый был 12, X доходит до 24 при Y = 12.

Дополнительно `HomeScreen.kt:1248` содержит нерабочую попытку ограничения:
`progress.coerceAtMost(totalEpisodes.coerceAtLeast(progress))` — алгебраически это тождество
`progress`, ничего не ограничивает.

`BatchEpisodeCheckUseCase` (каскад AniList → MAL → поиск) пишет только в промежуточную таблицу
`AnimeUpdate`, но не в `anime.episodes`; без явного действия пользователя поле остаётся старым.

### 3. Сезон в Kodik

`KodikSource.resolveEpisode` (строка 41) получает `seasonQuery = anime.seasonSourceQuery(seasonInfo)`
и запускает два пути параллельно:

- **direct** (`KodikDirectSearch.findEpisodeCandidates`) — получает `seasonNumber` и
  `seasonIdentifiable`, проверяет `last_season`, карту `seasons.{N}.episodes.{M}` и отказывается
  выдавать результат при недоказуемом сезоне ≥2 (`KodikDirectSearch.kt:104-110`). Исправлено в
  `season-source-resolution` TICKET-05.
- **yummy** (`KodikSource.yummyCandidates`, строка 100) — **о сезоне не знает ничего**.
  `findRelease(anime)` ищет по набору `[titleRu, title, titleEn]`, где `titleRu` намеренно
  оставлен франшизным (`SeasonSourceAnime.kt:19`), берёт релиз с лучшим счётом и выбирает серию
  по одному лишь номеру (`episodeMatches`, строка 177).

Для «Bottom-Tier Character Tomozaki 2nd Stage» набор запросов —
`["Низкоуровневый персонаж Томодзаки", "Bottom-Tier Character Tomozaki 2nd Stage"]`. Первый
запрос — это русское название **первого** сезона, оно же лежит в `localTitles`, поэтому релиз
первого сезона получает максимальный счёт. Серия 1 этого релиза = S1E1. Ровно наблюдаемый симптом.

Логкат подтверждает: `KodikSource: Resolved Kodik S2E1 dubbings=8 (yummy=7, direct=8)` — семь
кандидатов пришли yummy-путём, и после `distinctBy { it.iframeUrl }` они попали в общий список
вперемешку с корректными. Выбранная озвучка (`selectedSource=Kodik___Озвучка_AniLibria`) взялась
из чужого сезона.

Оба других источника в этот момент честно отказались:
`AniLibriaSource: No release matched … S2E1`, `AnimeGoSource: No season-confirmed match for S2E1`.

## Domain rules

- **«Лучше пусто, чем чужой сезон».** Инвариант из `season-source-resolution`, трижды пересиливший
  букву плана. Недоказуемая принадлежность релиза сезону = отказ, а не догадка.
- **Неизвестность не равна нулю.** «Число серий не разрешено» и «серий нет» — разные состояния.
- **Просмотр считается сквозной нумерацией по франшизе**, номер сезона к нему не относится
  (существующее решение, `AnimeCard.kt:135-139`). Знаменатель обязан быть в той же шкале.

## Required behavior

### FR-1. Индикатор загрузки не зависит от доков

Пока `showLoading` истинно, индикатор виден независимо от `controlsVisible`. Тап по видео,
автоскрытие доков и блокировка управления на него не влияют.

### FR-2. Индикатор загрузки виден в PiP

В режиме PiP при `showLoading` рисуется компактный индикатор поверх видео. Доки, кнопки, жесты и
подписи в PiP по-прежнему не композятся.

### FR-3. Анимация катаны удалена

Из проекта уходят `KatanaCycle`, `KatanaLoader`, `KatanaLoadingOverlay`, их тесты и неподключённый
`media/ui/FrozenFrame.kt` (ноль вызовов). Единственная точка применения катаны — ридер манги
(`MangaReaderScreen.kt:181`) — переводится на локальный (не полноэкранный) `BubbleClusterLoader`.

### FR-4. Знаменатель на карточке — в шкале франшизы

Y считается как сумма `SeasonInfo.episodes` по всем сезонам из `SeasonEpisodesStore`, то есть в
той же шкале, что и X. Сети не требуется: расклад уже разрешён и закэширован.

Когда расклад недоступен или пуст — показывается прежнее `anime.episodes`. Это не регресс:
для односезонных тайтлов обе шкалы совпадают.

### FR-5. Yummy-путь Kodik уважает сезон

Yummy-путь обязан подтвердить, что найденный релиз относится к запрошенному сезону. При сезоне ≥2
без подтверждения путь возвращает пусто, а не релиз первого сезона. Direct-путь при этом
продолжает работать самостоятельно.

## Failure and fallback behavior

- FR-4: нет расклада сезонов → знаменатель `anime.episodes`; нет и его → счётчик без знаменателя
  (существующая ветка `if (total != null)`).
- FR-5: yummy отказал → в выдаче остаются кандидаты direct-пути. Оба пусты → `SourceEngine`
  сообщает ноль хостеров, как и для любого нерезолвнутого сезона.

## Out of scope

- Полноэкранный оверлей загрузки в плеере: пользователь отверг эксперимент с катаной.
- Запись разрешённого числа серий в `anime.episodes` (мутация пользовательских данных).
- Сетевые запросы числа серий с главного экрана.
- Детерминированный прогресс загрузки (проценты).
- Кнопки управления в PiP.
- `AniLibriaSource` франшизный индекс — отдельный незакрытый TICKET-09 в
  `.scratch/season-source-resolution/`, к трём заявленным дефектам отношения не имеет.
- ~25 разнородных `CircularProgressIndicator` по проекту.

## Open questions

Нет. Три решения приняты пользователем в интервью 2026-08-02:

1. Катана удаляется, а не подключается в плеер — эксперимент признан неудачным
   (`SAFE_DEFAULT` не потребовался, решение явное).
2. Знаменатель — сумма по франшизе из `SeasonEpisodesStore`, без записи в БД и без сети.
3. В PiP показывается компактный индикатор загрузки.
