# TICKET-04: Yummy-путь Kodik обязан подтверждать сезон

## Status

DONE

## Objective

Закрыть выдачу серий первого сезона под видом второго: yummy-путь `KodikSource` должен
подтверждать принадлежность найденного релиза запрошенному сезону, а при недоказуемости —
возвращать пусто.

## User or system value

Наблюдаемый дефект: пользователь смотрел S1E11, открыл S2E1 — заиграла S1E1; открыл S2E2 —
заиграла S1E2. Это худший класс ошибки в проекте: пользователю молча подают чужой контент,
и он узнаёт об этом только по картинке.

## Dependencies

Нет.

## Scope

- `media/source/KodikSource.kt`, `yummyCandidates` (строка 100) и `findRelease` (строка 128):
  путь принимает `SeasonSourceQuery` вместо `Anime` и учитывает `seasonNumber` /
  `seasonIdentifiable`.
- Подтверждение сезона — чистая функция от названий релиза и `SeasonInfo`, по образцу
  `releaseIdentifiesSelectedSeason` (`AniLibriaSource.kt:319`): точное совпадение сезонного
  названия либо порядковый маркер. Переиспользовать существующую функцию, если она подходит без
  натягивания; иначе — своя, рядом с yummy-путём.
- При сезоне ≥2 без подтверждения yummy-путь возвращает пустой список.

## Out of scope

- `KodikDirectSearch` — его сезонная логика уже верна (TICKET-05 пакета
  `season-source-resolution`) и покрыта тестами.
- Нечёткое сопоставление названий: порог пропускает усечённое название соседнего сезона —
  ровно та ошибка, которую чиним.
- `AniLibriaSource` франшизный индекс (TICKET-09 чужого пакета).
- `AnimeGoSource` — в логе честно отказался, дефекта нет.

## Expected architecture impact

Yummy-путь дотягивается до того же контракта `SeasonSourceQuery`, которым уже пользуется
direct-путь. Оба пути `KodikSource` становятся сезонно-осведомлёнными, и «сезонная слепота»
перестаёт быть свойством одного из них.

## Risks

- **Потеря резолвов.** Yummy индексирует не всё, и строгое подтверждение обнулит часть выдачи
  там, где раньше был (возможно, верный) результат. Инвариант проекта «лучше пусто, чем чужой
  сезон» этот размен уже разрешил трижды.
- `titleRu` намеренно остаётся франшизным (`SeasonSourceAnime.kt:19`) — он единственный, чем
  русские каталоги находят тайтл. Убирать его из набора запросов нельзя: сломается поиск.
  Чинить надо подтверждение результата, а не сужение запроса.
- Тестов у yummy-пути сейчас нет — потребуется шов для подстановки ответа API.

## Implementation notes

Добавлена чистая функция `yummyReleaseServesSeason(releaseTitles, slug, seasonInfo)` в
`KodikSource.kt`. Она делегирует уже существующей `releaseIdentifiesSelectedSeason`
(`AniLibriaSource.kt:319`), добавляя только обработку «сезон не выбран» (`seasonInfo == null`).
Своё правило сопоставления не заводилось: у AniLibria оно ровно то же — точное совпадение с
сезонным названием либо порядковый маркер, — и раздваивать его значило бы гарантированно
получить два расходящихся понимания «релиз относится к сезону».

Слаг (`anime_url`) передаётся на место параметра `alias`: русские релизы часто несут номер
сезона только в адресе, а не в названии. Тест на это есть отдельный.

### Отсев стоит ДО выбора лучшего, а не после

Ключевое решение реализации. Наивный вариант «взять лучший по счёту, затем проверить сезон»
не работает: русское название франшизы — это название первого сезона, поэтому при сезоне ≥2
релиз первого сезона выигрывает счёт у правильного, и проверка после выбора просто отвергала бы
всё подряд, обнуляя yummy-путь целиком.

Поэтому неподтверждённые релизы отсеиваются внутри каждой ступени лестницы, до `maxByOrNull`.
Лестница идёт дальше и может найти нужный релиз следующим запросом — английским названием
сезона. Так путь сохраняет резолвы вместо того, чтобы просто замолчать.

### Попутно

`score()` дублировал извлечение названий релиза из JSON — вынесено в `releaseTitles(item)`,
которым теперь пользуются обе стороны. Иначе проверка сезона и подсчёт совпадения смотрели бы
на разные наборы названий.

Добавлена строка лога при отказе: `Yummy: no season-confirmed release for S{n} (N rejected)` —
прежний лог не мог показать расхождение вовсе (см. журнал: он печатал ЗАПРОШЕННЫЙ номер сезона,
а не найденный, поэтому дефект был невидим).

## Deviations

- **Planned:** «Строка лога `Resolved Kodik S{n}E{m}` различает вклад путей».
- **Actual:** строка не менялась — она уже несёт `yummy=/direct=`. Вместо этого добавлена
  отдельная строка на отказ yummy-пути по сезону.
- **Reason:** критерий был уже выполнен до тикета, а недостающей была диагностика ОТКАЗА,
  которой не существовало.
- **Consequence:** нет; наблюдаемость выросла.
- **Follow-up:** нет.

## Review findings

Самопроверка по диффу, блокирующих находок нет.

- **Спека.** FR-5 закрыт. AC-6 подтверждён отрицательным тестом на реальном контрпримере из
  логката. Direct-путь не тронут — он и не был сломан.
- **Инвариант «лучше пусто, чем чужой сезон»** (соблюдён). Недоказуемый сезон ≥2 даёт пусто.
  Это четвёртый случай в проекте, когда инвариант пересиливает удобство.
- **Регресс на односезонных** (проверен). `seasonInfo == null` и `seasonNumber <= 1` возвращают
  `true` без проверок — прежнее поведение сохранено, оба случая под тестом.
- **Потеря резолвов** (IMPORTANT_FOLLOW_UP, принято). Строгое подтверждение обнулит часть выдачи
  yummy-пути там, где раньше мог быть верный результат. Размен разрешён инвариантом; отсев до
  выбора лучшего смягчает его, сохраняя лестницу. Direct-путь продолжает работать независимо.
- **`titleRu` не сужался** (соблюдено). Набор запросов не изменился — сломался бы поиск в
  русских каталогах. Починен результат, а не запрос, как и требовал план.
- **Архитектурный наблюдатель.** Долг уменьшен: оба пути `KodikSource` стали сезонно-
  осведомлёнными, «сезонная слепота» перестала быть свойством одного из них. Правило
  принадлежности релиза сезону осталось в ОДНОМ месте на весь проект
  (`releaseIdentifiesSelectedSeason`), новой копии не появилось. Дублирование извлечения
  названий устранено попутно и в пределах того же файла.
