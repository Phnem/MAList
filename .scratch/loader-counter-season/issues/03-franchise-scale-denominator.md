# TICKET-03: Знаменатель прогресса на карточке — в шкале франшизы

## Status

DONE

## Objective

Считать «всего серий» на карточке главного экрана в той же шкале, что и «просмотрено»: суммой
серий всех сезонов из `SeasonEpisodesStore`, а не плоским полем `anime.episodes`.

## User or system value

Сейчас на карточке выходит «15 / 12»: числитель сквозной по франшизе, знаменатель — один сезон.
Числа в одной строке живут в разных шкалах, и на любом многосезонном тайтле счётчик перескакивает
собственный предел.

## Expected architecture impact

`HomeScreen` перестаёт суммировать сезоны в теле `remember` и получает готовое число.
Знание о том, как шкала просмотра соотносится с раскладом сезонов, оседает в одном месте
рядом с уже существующей сквозной логикой `HomeViewModel.watchedEpisodes`.

## Risks

- Расклад бывает неполным (`complete = false`) и у онгоингов растёт: сумма будет ниже
  анонсированной. Это соответствует существующей семантике `SeasonInfo.episodes` («доступно
  сейчас»), но знаменатель будет меняться со временем — убедиться, что это не выглядит ошибкой.
- «Расклад не готов» нельзя превращать в 0 — прямое нарушение доменного правила проекта.
- `watchedEpisodes` и знаменатель обязаны читать один и тот же расклад, иначе шкалы снова
  разъедутся.

## Implementation notes

Новый файл `domain/seasons/FranchiseEpisodeTotal.kt` — одна чистая функция
`franchiseEpisodeTotal(layout, storedEpisodes)`: сумма `SeasonInfo.episodes` по раскладу, а при
нулевой сумме — прежнее `storedEpisodes`.

`HomeViewModel` получил `seasonLayouts` — тот же `seasonEpisodesStore.flow`, по которому уже
считается `watchedEpisodes`. Это ключевое требование обзора архитектуры: числитель и знаменатель
обязаны читать один расклад, иначе шкалы разъедутся снова при первой же правке.

`HomeScreen` подставляет `franchiseEpisodeTotal(seasonLayoutMap[anime.id], anime.episodes)`
вместо сырого `anime.episodes`, а нерабочее ограничение
`progress.coerceAtMost(totalEpisodes.coerceAtLeast(progress))` заменено на `progress`.

### Почему числитель не подрезается

Ограничение было тождеством `progress` — `min(p, max(t, p)) == p` при любых значениях, — то есть
попытка защиты, которая никогда не срабатывала. Заменять его работающим зажимом нельзя: тогда на
неразрешённом раскладе карточка показывала бы «12 / 12» вместо реальных 15 просмотренных, то
есть врала бы пользователю. Правильное место починки — знаменатель, что тикет и делает.

### Свойство, которое закрывает исходный дефект

Числитель = `сумма серий сезонов до текущего + номер текущей серии`. Знаменатель = `сумма серий
ВСЕХ сезонов расклада`. Пока расклад содержит текущий сезон, знаменатель не может оказаться
меньше числителя — это следует из построения, а не из удачной подгонки. Свойство закреплено
тестом-перебором по всем сезонам и сериям трёхсезонной франшизы.

## Review findings

Самопроверка по диффу, блокирующих находок нет.

- **Спека.** FR-4 закрыт; AC-4 и AC-5 подтверждены тестами. Ветки `AIRING` и `READING` в
  `rememberCardProgress` не тронуты — у них своя шкала и свои источники.
- **Доменное правило «неизвестность ≠ ноль»** (соблюдено). Пустой и отсутствующий расклад
  возвращают `storedEpisodes`, а не 0; при `storedEpisodes = 0` счётчик остаётся без
  знаменателя, как и раньше. Оба случая закреплены тестами.
- **Не мутируем данные пользователя** (соблюдено). `anime.episodes` не переписывается; расчёт
  живёт в отображении. Сети на главном экране не добавилось — расклад уже загружен.
- **Неполный расклад занижает знаменатель** (IMPORTANT_FOLLOW_UP, принято). Если резолвнут
  только первый сезон многосезонного тайтла, сумма меньше настоящей, и «просмотрено > всего»
  теоретически может уцелеть. Это строго лучше прежнего поведения и не лечится без сети,
  которую тикет исключает. Записано в известные ограничения.
- **Знаменатель у онгоинга растёт со временем** (OPTIONAL, принято). Прямое следствие семантики
  `SeasonInfo.episodes` = «доступно сейчас». Осознанно: числитель живёт в той же шкале.
- **Архитектурный наблюдатель.** Долга не добавлено. `HomeScreen` перестал складывать сезоны в
  теле `remember` и получает готовое число; знание о шкале осело в одной тестируемой функции без
  зависимостей от Android. `seasonLayouts` — прямое переизложение стора, лишнего слоя не
  появилось.
