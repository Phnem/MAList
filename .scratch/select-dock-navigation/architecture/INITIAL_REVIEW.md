# Архитектурный разбор до декомпозиции

Область разбора ограничена задачей: корневая навигация, главный экран, карточки, статистика. Общая уборка кодовой базы в область не входит.

## 1. Какие границы помогают, какие мешают

**Помогают**

- `AppNavGraph` уже type-safe и изолирует переходы; push-экраны (Details, AddEdit-по-id) продолжат работать без изменений.
- `MotionTokens` даёт готовый словарь пружин (`sheetPresent`, `sheetDismissForced`, `standard`) — «наезд» не изобретает свою физику.
- `DetailsMiniDock` / `InspectModeDock` — фактически один и тот же компонент, скопированный дважды. Появление третьей копии (док рабочей области) — сигнал вынести общий `SelectDock`.
- `homeScrollBlur(blurAmount)` уже умеет блюрить контент главной, не добавляя и не убирая узлы над `layerBackdrop`. Контекстное меню карточки переиспользует именно его.
- Подтверждающие шторки (`AnimeMenuSheet`) уже отвязаны от жеста: они управляются состоянием `animeToDelete` / `animeToFavorite`. Меню по удержанию просто выставляет то же состояние.

**Мешают**

- `HomeScreen` — 1262 строки, один композабл, держит состояние всех оверлеев (`showCSheet`, `showSortOverlay`, `showNotificationsOverlay`, `isSearchVisible`, `animeToDelete`, `animeToFavorite`, `isDockVisible`, `layerBackdropResetKey`). Часть этого состояния (видимость дока) должна переехать в рабочую область, часть остаётся страницей.
- `GlassBottomNavigation` совмещает три роли: визуал капсулы, источники shared-element, вызовы навигации. Как select-док он должен уметь только «показать выбор» и «сообщить о выборе».
- `StatsOverlay` смешивает форму подачи (шторка: граббер, свайп, скрим, задержка на закрытие) с содержимым (колода, детальный режим, ИИ-объяснения). Извлечь содержимое — обязательное условие R6.
- `SettingsScreen` и `InspectScreen` содержат собственные шапки с кнопкой «назад» и знают про `navController` — как страницы им нужен способ сказать «перелистни на Настройки» вместо «открой Настройки».

## 2. Нужен ли прerefactor до фичи

Да, ровно два, и оба узкие:

1. **Извлечь содержимое статистики** из `StatsOverlay` в `StatsContent` — иначе страница получится копипастой шторки. Делается внутри тикета статистики, не отдельным.
2. **Общий `SelectDock`** вместо третьей копии мини-дока. Делается внутри тикета дока.

Широкая декомпозиция `HomeScreen` **не требуется** и в область не входит: главная переезжает в страницу целиком, как есть. Трогаем только то, что мешает (видимость дока, механика жестов карточек).

## 3. Что должно остаться стабильным

- Слой данных, ViewModel'и, доменные сервисы — не трогаем вовсе.
- `Details`, `AddEdit`-по-id, диплинк из уведомления — контракт неизменен.
- `layerBackdrop` / `adaptiveGlassBackdrop` — не трогаем реализацию; только соблюдаем её правила.

## 4. Где прячем сложность

| Сложность | За каким интерфейсом |
|---|---|
| Порядок страниц, резолв Back, соответствие «страница ↔ сегмент» | `WorkspacePage` (enum) + `WorkspaceNavState` — чистые, тестируемые |
| Математика «наезда» | Чистая функция `workspacePageTransform(offset)` → data-класс |
| Правило подъёма выделенной карточки | Чистая функция `cardLiftFor(bounds, menuHeight, viewport, dockInset)` |
| Живое/статичное стекло | Один флаг внутри дока, снаружи — только `isMoving: Boolean` |
| Отдельная VM у страницы «Добавить» | `koinViewModel(key = ...)` внутри страницы, наружу не течёт |

## 5. Какие публичные интерфейсы поменяются

- `HomeScreen(...)` получает параметры вместо собственных решений: видимость дока наружу, признак «карточки в режиме меню».
- `InspectScreen(...)`, `SettingsScreen(...)` получают необязательный `onBack` (null = кнопки нет) и `onOpenSettings`-подобные колбэки вместо прямых `navigate*`.
- `AddEditScreen(...)` получает `onSaved: () -> Unit` вместо жёсткого `popBackStack()` в обработчике эффекта.
- `StatsOverlay` остаётся (для выключенного флага), рядом появляется `StatsContent` и `StatsPage`.

## 7. Архитектурные риски, за которыми следят ревью тикетов

1. **Инвалидация `layerBackdrop`.** В каждом ревью проверяем: не появился ли новый узел-предок над `layerBackdrop`, который добавляется/удаляется структурно, и не поехал ли `scale`/`clip`/`RenderEffect` на предке. Правило из кодовой базы: свойства — можно, структуру — нельзя.
2. **Дублирование ключей shared-element.** При включённом флаге старый док не существует, поэтому ключи `inspect_container` / `fab_container` / `settings_container` остаются в одном экземпляре. Ревью следит, чтобы обе навигации никогда не были смонтированы одновременно.
3. **Двойное состояние из-за флага.** Соблазн размазать `if (flag)` по десяткам мест. Правило: ветвление ровно в одной точке — в `composable<HomeRoute>`; ниже по дереву флаг не читается, кроме механики жестов карточки (там он прокидывается параметром).
4. **Вложенные пейджеры по одной оси** (Кадр). Приняли осознанно; ревью тикета 07 проверяет, что жест действительно передаётся наружу и не залипает.
5. **Расползание задачи в редизайн статистики.** Ревью тикета 05 сверяет диф с «тот же контент, другая форма».
