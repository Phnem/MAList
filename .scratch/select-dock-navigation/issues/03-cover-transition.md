# TICKET-03: «Наезд» между страницами

Status: IN_PROGRESS — код готов, тесты зелёные, ждёт проверки на устройстве

## Objective

Заменить дефолтный синхронный свайп пейджера наездом: нижняя страница углубляется и параллаксит, верхняя едет полностью и рисуется поверх.

## Dependencies

TICKET-01.

## Scope

- Чистая функция `workspacePageTransform(offset: Float): PageTransform` → `scale`, `translationXFraction`, `dimAlpha`, `cornerDp`, `shadowAlpha`, `zIndex`.
  - `offset` — знаковое смещение страницы относительно текущей (`page - currentPage + currentPageOffsetFraction`).
  - Уходящая (нижняя) страница: `scale` 1 → 0.94, `translationX` = 25 % от полного хода, притухание, скругление углов до 16dp.
  - Наезжающая: полный ход, тень по ведущему краю, выше по `zIndex`.
- Применение трансформации в `WorkspaceScreen` через `graphicsLayer` **на содержимом страницы**, не на предках `layerBackdrop` (см. архитектурный разбор, риск 1).
- Одинаковый результат для жеста, тапа по доку и Back (используем `animateScrollToPage` с `MotionTokens.sheetPresent()`).

## Out of scope

Стекло дока (TICKET-04), содержимое страниц.

- [x] Верхняя страница едет за пальцем один в один и перекрывает нижнюю с тенью по краю
- [x] Программное перелистывание (док, Back) даёт тот же переход — оба идут через `animateScrollToPage`, трансформация читает то же состояние пейджера

- [ ] Док не «схлопывается» в плоскую заливку после серии переходов — на устройстве

## Implementation notes

- Чистая функция и модель — `ui/workspace/WorkspacePageTransform.kt`, тесты —
  `test/.../WorkspacePageTransformTest.kt` (написаны до реализации, красный прогон получен).
- Роль страницы определяет ЗНАК смещения: `offset >= 0` — наезжающая, `< 0` — уходящая. Отсюда
  автоматически следует, что страница с бо́льшим индексом всегда лежит выше, и одно правило
  работает в обе стороны (вперёд — соседка тонет, назад — всплывает из-под уезжающей).
- Применение — `Modifier.workspacePageMotion(pagerState, index)` в `WorkspaceScreen.kt`:
  `zIndex(index)` статичный (индекс не меняется), состояние пейджера читается ВНУТРИ лямбд
  `graphicsLayer` и `drawWithContent` — жест не перекомпоновывает страницы.
- Тень по ведущему краю — `shadowElevation` слоя (до 24dp): нарисовать её кистью нельзя,
  за пределы клипа страницы кисть не достаёт.

## Deviations

1. **`PageTransform` без `zIndex`.** В спеке поле было; на деле порядок задаётся индексом
   страницы и не зависит от смещения, поэтому zIndex статичен и в модель не попал — иначе он
   был бы значением, которое каждый кадр считается и никогда не меняется.
2. **`translationXFraction` — это ДОБАВКА к ходу пейджера**, а не итоговое смещение. Тесты
   проверяют именно итог (`offset + translationXFraction == offset * 0.25`), чтобы смысл поля
   нельзя было потерять при рефакторинге.
3. **Исправлен знак смещения (после проверки пользователем).** Первая версия считала
   `(page - currentPage) + currentPageOffsetFraction`. Знак дроби противоположный: она растёт,
   когда страницы едут ВЛЕВО. Из-за этого при перетаскивании обе видимые страницы попадали в
   ветку «наезжающая» (трансформация нулевая), и наезда не было видно вообще. Формула вынесена
   в чистую `workspacePageOffset()` и закрыта отдельным `WorkspacePageOffsetTest` — там есть
   тест на сам инвариант «две видимые страницы никогда не в одной роли».
