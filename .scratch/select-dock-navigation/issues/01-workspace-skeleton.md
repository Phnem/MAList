# TICKET-01: Dev-флаг и каркас рабочей области

Status: IN_PROGRESS — код готов, ждёт проверки на устройстве

## Objective

Ввести флаг `SELECT_DOCK_NAVIGATION` и рабочую область: пейджер из пяти страниц с рабочим доком-селектором и правилом «Назад → Главная». Переход пока дефолтный пейджерный, стекло и полировка — в следующих тикетах.

## User or system value

Сквозной тракер: при включённом флаге по приложению уже можно ходить свайпами и доком, все пять разделов на месте. При выключенном — ничего не изменилось.

## Dependencies

Нет.

## Scope

- `DevPreferencesKeys.SELECT_DOCK_NAVIGATION` (отсутствие ключа = ВЫКЛ) + тумблер в разделе разработчика настроек + чтение в `SettingsViewModel`.
- `WorkspacePage` — enum из пяти значений с индексами: `FRAME(0)`, `STATS(1)`, `HOME(2)`, `ADD(3)`, `SETTINGS(4)`.
- `WorkspaceScreen` — `HorizontalPager(pageCount = 5, initialPage = HOME, beyondViewportPageCount = 1)`, страницы: `InspectScreen`, заглушка статистики, `HomeScreen`, `AddEditScreen(animeId = null)`, `SettingsScreen`.
- `WorkspaceDock` — пять сегментов на общем `SelectDock` (визуальный контракт `DetailsMiniDock`), пока со статичной заливкой.
- `BackHandler`: страница ≠ HOME → анимированно на HOME; на HOME — не перехватываем.
- Ветвление по флагу ровно в одной точке — `composable<HomeRoute>` в `NavGraph.kt`.

## Out of scope

«Наезд», стекло дока, автоскрытие дока, механика карточек, страница статистики, поведение черновика, шапки Кадра и Настроек.

## Acceptance criteria

- [ ] Флаг виден в настройках разработчика, по умолчанию выключен, состояние переживает перезапуск
- [ ] Флаг выключен → навигация идентична текущей (старый док, старые маршруты)
- [ ] Флаг включён → старт на Главной, свайп листает по порядку Кадр · Статистика · Главная · Добавить · Настройки
- [ ] Тап по сегменту дока листает к странице анимированно; активный сегмент соответствует видимой странице (включая ситуацию «палец бросил на полпути»)
- [ ] Back с любой страницы ≠ Главная возвращает на Главную; с Главной закрывает приложение
- [ ] Details и AddEdit-по-id открываются push-экранами поверх рабочей области; Back из них возвращает в рабочую область на ту же страницу
- [ ] Диплинк из уведомления открывает Details поверх рабочей области
- [ ] `:app:compileDebugKotlin` и `:app:assembleDebug` проходят

## Verification plan

Unit: резолв `WorkspacePage` по индексу и правило Back. Сборка. Ручная проверка на устройстве: обход всех пяти страниц свайпом и доком, Back с каждой, push Details/AddEdit и возврат, тап по уведомлению.

## TDD classification

RECOMMENDED — для `WorkspacePage` и правила Back (чистая логика). Остальное — визуальное.

## Expected architecture impact

Новый слой между `NavHost` и экранами. `HomeScreen`, `InspectScreen`, `SettingsScreen`, `AddEditScreen` начинают вызываться из двух мест — их сигнатуры должны это выдерживать без ветвлений внутри.

## Risks

- Двойной монтаж старой и новой навигации → дублирование ключей shared-element. Митигация: ветвление в одной точке.
- `AddEditScreen` на странице делает `popBackStack()` при сохранении — до TICKET-06 это уронит пользователя из рабочей области. Временная мера: на странице колбэк сохранения не подключаем, кнопку сохранения на странице считаем неготовой (проверяется только навигация).

## Implementation notes

Новые файлы:

- `ui/workspace/WorkspacePage.kt` — enum + чистая логика (`ofIndex`, `backTargetFrom`), без Compose.
- `ui/workspace/WorkspaceDock.kt` — док-селектор на пять сегментов, пока со статичной заливкой.
- `ui/workspace/WorkspaceScreen.kt` — пейджер, BackHandler, размещение дока.
- `app/src/test/.../WorkspacePageTest.kt` — 6 тестов.

Изменённые файлы:

- `DevPreferencesKeys` — ключ `SELECT_DOCK_NAVIGATION` (отсутствие = ВЫКЛ).
- `SettingsUiState` / `SettingsViewModel` — чтение и сеттер.
- `SettingsScreen` — строка тумблера в разделе «Разработчик».
- `NavGraph` — ветвление в `composable<HomeRoute>`, единственная точка чтения флага.
- `HomeScreen` — параметр `showBottomDock` (страница не рисует свой док).
- `AddEditScreen` — необязательный `onSaved`.
- `InspectScreen`, `SettingsScreen` — необязательный `onBack`.

Решения по ходу:

- Подписи дока и тумблера зашиты в коде, а не в `UiStrings`: там 252 поля из 254 допустимых, за пределом RELEASE падает с VerifyError в clinit. Обе поверхности временные.
- Пилюля дока следует за `pagerState.targetPage`, а не за `settledPage`: иначе она стоит на старом разделе до конца анимации и потом прыгает.
- `BackHandler` рабочей области тоже считает от `targetPage` — Back посреди броска не уводит не туда.
- Икона раздела «Кадр» — тот же ассет `frame_inspect_24`, что у старого дока.

Правка после первой проверки на устройстве: боковая подпись у активного сегмента (паттерн `DetailsMiniDock`) для пяти вкладок не работает — подписи обрезались, сегменты наезжали друг на друга, полупрозрачная заливка пропускала контент списка. Док переведён на раскладку нижней навигации Telegram / прежнего `GlassBottomNavigation`: подпись ПОД иконкой 8.5sp, пилюля только за иконкой, ширина колонок долевая (`weight`).

Вторая правка после сравнения со старым доком: дело было не в раскладке, а в материале и масштабе. Взяты размеры прежнего дока (капсула 74dp, иконки 32dp в боксе 36dp вместо 22dp) и живое стекло — `adaptiveGlassBackdrop` + `GlassPreset.CompactNav`, как у `GlassBottomNavigation` и мини-дока Details. Для этого в `WorkspaceScreen` появился свой `rememberLayerBackdrop`, оборачивающий пейджер: ровно тот приём, что уже работает в `DetailsScreen`, где такой же док висит над горизонтальным пейджером. Живое стекло было запланировано в TICKET-04 — вытянуто сюда, потому что без него док визуально не принимается.

## Deviations

1. **Планировалось:** сохранение на странице «Добавить» не подключать, считать неготовым до TICKET-06.
   **Сделано:** добавлен необязательный `onSaved` в `AddEditScreen`, страница передаёт «перелистнуть на Главную».
   **Причина:** без этого `popBackStack()` со страницы выбрасывал бы из рабочей области на Welcome — проверять навигацию в таком состоянии невозможно.
   **Следствие:** первый пункт TICKET-06 выполнен авансом; там остаётся сброс черновика и верификация.

2. **Планировалось:** кнопки «назад» на Кадре и Настройках трогает TICKET-07.
   **Сделано:** добавлен необязательный `onBack`, страницы передают «на Главную».
   **Причина:** та же — `popBackStack()` со страницы ломает стек.
   **Следствие:** TICKET-07 теперь про скрытие кнопок и промо ИИ, а не про отвязку от стека.

3. **Планировалось:** отдельная инстанция ViewModel для страницы «Добавить» — TICKET-06.
   **Сделано:** сразу, `koinViewModel(key = "workspace_add_edit")`.
   **Причина:** общая на граф инстанция немедленно давала бы взаимное затирание черновика и редактирования, то есть заведомо неверную ручную проверку.
   **Следствие:** в TICKET-06 остаётся правило сброса черновика.

## Review findings

Самопроверка по рискам архитектурного разбора:

| Риск | Результат |
|---|---|
| Дублирование ключей shared-element | НЕТ: ветвление одно, две навигации не сосуществуют |
| Флаг размазан по дереву | НЕТ: читается ровно в `composable<HomeRoute>` |
| Структурная смена узлов над `layerBackdrop` | `showBottomDock` постоянен на всё время жизни вызова, не переключается на лету. НО пейджер добавляет трансформируемого предка над контентом Главной — проверяемо только на устройстве, см. ниже |
| Расползание задачи | Три отклонения, все зафиксированы выше |

Известное ограничение (не блокирующее): у страниц Настроек и Кадра есть свои `BackHandler`, завязанные на локальное состояние оверлеев. Если фоновая операция откроет диалог на НЕактивной странице (например, доклад «Исправить БД» пока вы на Главной), её обработчик перехватит Back раньше рабочей области. Сценарий редкий; полное решение — гасить обработчики неактивных страниц, кандидат в TICKET-08 или в отдельный тикет.
