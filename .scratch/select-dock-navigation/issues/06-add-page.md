# TICKET-06: Страница «Добавить»

Status: PENDING

## Objective

Сделать «Добавить» полноценной страницей: своя инстанция ViewModel, сброс черновика при уходе, переход на Главную после сохранения. Редактирование по id остаётся push-экраном.

## Dependencies

TICKET-01.

## Scope

- Отвязать `AddEditScreen` от `popBackStack()`: обработчик `AddEditEffect.NavigateBack` вызывает переданный `onSaved` / `onClose`.
- Страница использует отдельную инстанцию `AddEditViewModel` (`koinViewModel(key = ...)`), не ту, что у push-экрана редактирования.
- Уход со страницы (жест или док) сбрасывает черновик: `loadAnime(null)` при уходе с индекса `ADD`.
- После успешного сохранения — `animateScrollToPage(HOME)`.
- На странице нет кнопки «назад» в шапке.

## Out of scope

Изменение формы, полей, валидации, логики сохранения.

## Acceptance criteria

- [ ] Страница «Добавить» открывается всегда чистой: заполнить наполовину, свайпнуть на Главную, вернуться — поля пустые
- [ ] Сохранение создаёт запись и рабочая область оказывается на Главной, новая запись видна в списке
- [ ] Ошибка сохранения оставляет на странице с введёнными данными и показывает сообщение
- [ ] Карандаш на карточке открывает push-экран редактирования; черновик страницы «Добавить» им не затирается и наоборот
- [ ] Сохранение на push-экране редактирования по-прежнему возвращает назад (`popBackStack`)
- [ ] При выключенном флаге маршрут «Добавить» работает как раньше

## Verification plan

Ручная: заполнить/уйти/вернуться; сохранить; сохранить с ошибкой (пустой обязательный ввод); открыть Edit по id при заполненной странице и проверить оба состояния. Сборка.

## TDD classification

RECOMMENDED — правило «когда сбрасывать черновик» вынести в чистую функцию от смены страницы и покрыть тестом.

## Risks

Две инстанции одной ViewModel в Koin — легко получить общую по невнимательности; проверить, что ключи действительно разные и состояния независимы.
