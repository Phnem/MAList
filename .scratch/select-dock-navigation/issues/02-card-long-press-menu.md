# TICKET-02: Контекстное меню карточки по долгому удержанию

Status: IN_PROGRESS — код готов, ждёт проверки на устройстве

## Objective

Заменить свайп-механику карточек модальным меню по долгому удержанию: карточка поднимается, фон блюрится и темнеет, под карточкой всплывают четыре действия.

## User or system value

Горизонтальная ось освобождается под навигацию, а действия над карточкой становятся явными и перестают срабатывать случайно.

## Dependencies

TICKET-01 (флаг).

## Scope

- Снять `SwipeToDismissBox` с карточек при включённом флаге; при выключенном — оставить как есть.
- Состояние выделения: `animeId` + границы карточки (`onGloballyPositioned`).
- Оверлей поверх заблюренного контента: копия карточки в анимированной позиции + ряд кнопок ✩ / 🗑 / ✎ / ⓘ.
- Чистая функция подъёма: `cardLiftFor(cardTop, cardHeight, menuHeight, viewportHeight, dockInset) -> liftPx`.
- Модальность: скрим перехватывает скролл, свайп страниц и док; тап по скриму снимает выделение.
- Переиспользовать существующий `homeScrollBlur` — новых узлов над `layerBackdrop` не добавлять.
- Копия карточки рендерится БЕЗ модификаторов shared-element (ключи уже заняты карточкой в списке).
- Тактильный отклик в момент срабатывания удержания.

## Out of scope

Изменение подтверждающих шторок, undo, меню на карточках результатов API-поиска.

## Acceptance criteria

- [ ] Горизонтальный свайп по карточке при включённом флаге листает страницы, а не открывает избранное/удаление
- [ ] Долгое удержание увеличивает карточку, блюрит и затемняет фон, показывает четыре кнопки с анимацией появления
- [ ] После отпускания пальца выделение сохраняется
- [ ] Скролл списка, свайп страниц и док не реагируют, пока карточка выделена
- [ ] Тап по пустому месту снимает выделение
- [ ] Карточка у нижнего края подъезжает вверх так, что весь ряд кнопок виден над доком; карточка в середине списка не двигается
- [ ] Звезда → шторка подтверждения избранного; мусорка → шторка подтверждения удаления; карандаш → AddEdit по id; i → Details
- [ ] После любого действия выделение снимается
- [ ] Выделение снимается, если запись пропала из списка
- [ ] Флаг выключен → свайпы работают как раньше
- [ ] Док остаётся стеклянным после открытия и закрытия меню (не «плоским»)

## Expected architecture impact

Карточка получает переиспользуемое содержимое без shared-element модификаторов. Состояние выделения живёт на уровне страницы Главная.

## Risks

- Копия карточки может «прыгнуть» относительно оригинала на первом кадре — нужна точная передача границ.
- Блюр + модальный слой близко к известному багу инвалидации стекла: следовать существующему пути `shouldBlur`, а не добавлять свой.

## Implementation notes

Новые файлы:

- `ui/home/cardmenu/CardLift.kt` — чистая `cardLiftFor`.
- `ui/home/cardmenu/CardActionMenu.kt` — `CardMenuTarget` + `CardActionMenuOverlay` (скрим, поднятая копия карточки, ряд из четырёх круглых кнопок).
- `app/src/test/.../CardLiftTest.kt` — 6 тестов.

Изменённые файлы:

- `AnimeCard.kt` — карточка разведена на `AnimeCardBody` (тело, переиспользуется копией в оверлее) и обёртку `SharedTransitionScope.OneUiAnimeCard`, которая накладывает модификаторы shared-element. Копия в оверлее рисует тело БЕЗ них: второй узел с тем же ключом Compose не разрешает.
- `ModifierExt.kt` — у `fluidClickable` появился необязательный `onLongClick` (null → прежний `clickable`, поведение всех текущих вызовов не меняется).
- `HomeScreen.kt` — параметры `useLongPressCardMenu` и `onCardSelectionChange`; расчёт состояния карточки поднят над развилкой «свайпы / удержание»; состояние `cardMenuTarget`; оверлей на `zIndex(50f)`.
- `WorkspaceScreen.kt` — `cardSelectionActive`: гасит док и выключает `userScrollEnabled` пейджера.
- `WorkspaceDock.kt` — параметр `dimmed`.

Решения по ходу:

- Блюр фона НЕ добавлялся новым слоем: `cardMenuTarget` включён в существующий `shouldBlur`, который кормит `homeScrollBlur`. Свой слой блюра был бы ещё одним узлом над `layerBackdrop`.
- Восстановление стекла после закрытия меню приехало бесплатно: `GlassBackdropRecovery` уже смотрит на `shouldBlur`.
- Скрим гасит и тапы (`detectTapGestures` → сброс), и перетаскивания (`detectDragGestures` с `consume()`). Без второго палец по скриму листал бы страницы: `clickable` перетаскивания не перехватывает.
- Док — сосед главной, а не потомок, поэтому скрим до него не достаёт: состояние выделения уходит наверх колбэком, и рабочая область сама гасит док и запирает пейджер.
- Границы карточки ловятся в координатах корня, а оверлей вычитает собственное начало координат: без этого копия уезжала бы на величину смещения оверлея.
