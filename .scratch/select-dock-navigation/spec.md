# Select-item dock navigation

Status: APPROVED (интервью завершено 2026-08-08)

## Problem

Нижний док — подложка-лаунчер: тап по иконке открывает отдельный экран (`InspectRoute`, `SettingsRoute`, `AddEditRoute`) или всплывающую шторку (статистика). Это не совпадает с языком навигации, который уже сложился в остальном приложении: в Details и в «Кадре» док — селектор, а перемещение между разделами делается свайпом.

Перенести этот язык на корневую навигацию мешают три вещи:

1. горизонтальный свайп на главной уже занят карточками (избранное / удаление);
2. статистика — bottom sheet, у неё нет формы страницы;
3. обычный свайп пейджера не даёт того ощущения глубины, что даёт фирменная шторка, наезжающая на фон.

## Desired outcome

Корень приложения — «рабочая область» из пяти равноправных страниц, между которыми ходят свайпом или тапом по доку-селектору. Карточки коллекции отдают горизонтальную ось навигации, а свои действия получают через контекстное меню по долгому удержанию.

## Current behavior

- `AppNavGraph`: Splash → Welcome → **Home** → {Details, AddEdit, Settings, Inspect}.
- `GlassBottomNavigation` (glass.kt:294): Кадр → `navigateToInspect()`, Статистика → `showCSheet = true` (оверлей поверх Home), Добавить → `navigateToAddEdit()`, Настройки → `navigateToSettings()`.
- Иконки дока — источники shared-element переходов (`inspect_container`, `fab_container`, `settings_container` + парные `*_icon`).
- Док прячется при скролле вниз (`nestedScrollConnection` → `isDockVisible`).
- Каждая карточка обёрнута в `SwipeToDismissBox`: вправо → шторка подтверждения «в избранное», влево → шторка подтверждения удаления.
- `StatsOverlay` — bottom sheet: `iosSheetContainer`, `GrabberHandle`, `rememberIosSheetSwipe`, скрим; внутри вертикальная колода из трёх карточек и детальный режим по тапу.
- Единственный внешний вызов из другого экрана: `InspectScreen.kt:198` → `navigateToSettings()` (промо «подключить ИИ»).

## Required behavior

### R1. Рабочая область и порядок страниц

Четыре страницы в фиксированном порядке: **Кадр (0) · Главная (1) · Добавить (2) · Настройки (3)**. Стартовая страница — Главная. Перемещение: горизонтальный свайп или тап по сегменту дока.

> Изменено 2026-08-08: страниц было пять, статистика убрана из дока — см. R6.

### R2. Док-селектор

Один док на всю рабочую область, поверх страниц. Активный сегмент — светлая пилюля с выезжающей подписью, неактивные — приглушённые иконки (визуальный контракт `DetailsMiniDock` / `InspectModeDock`). Док прячется при скролле вниз и возвращается при скролле вверх — как сейчас.

### R3. «Наезд»

Уходящая (нижняя) страница: `scale` 1 → 0.94, притухание, скругление углов, смещение по X на ~25 % хода пальца. Наезжающая (верхняя) страница: полный ход, тень по ведущему краю, рисуется поверх. Жест и программное перелистывание (тап по доку, Back) дают один и тот же переход.

### R4. Кнопка «Назад»

С любой страницы ≠ Главная — анимированный возврат на Главную тем же переходом. С Главной — стандартный выход из приложения. Внутренние состояния страницы (открытая шторка, поиск, выделенная карточка) перехватывают Back раньше — как сейчас.

### R5. Контекстное меню карточки

`SwipeToDismissBox` с карточек снимается. Долгое удержание:

- карточка увеличивается и поднимается над остальным контентом;
- всё позади блюрится и затемняется;
- под карточкой анимированно всплывает ряд из четырёх круглых кнопок: **избранное** (звезда), **удалить** (мусорка), **редактировать** (карандаш), **детали** (i в кружке);
- если под карточкой не хватает места, она подъезжает вверх ровно настолько, чтобы ряд кнопок влез целиком над доком;
- после отпускания пальца состояние сохраняется;
- сброс — нажатие любой кнопки или тап по пустому месту.

Состояние **полностью модально**: пока карточка выделена, не работают скролл списка, свайп страниц и док.

Действия кнопок:

| Кнопка | Поведение |
|---|---|
| Звезда | Существующая шторка подтверждения (`AnimeMenuSheet`, режим favorite/unfavorite) |
| Мусорка | Существующая шторка подтверждения удаления |
| Карандаш | `navigateToAddEdit(anime.id)` — push поверх рабочей области |
| i | `navigateToDetails(anime.id)` — push поверх рабочей области |

Кнопка Edit на самой карточке остаётся.

### R6. Статистика и панель подключения

Статистика **остаётся bottom sheet** и не становится страницей. Точка входа — средняя кнопка ВЕРХНЕГО дока на главной.

Панель подключения и синхронизации, занимавшая эту кнопку, переезжает отдельным пунктом «Синхронизация» в настройки. Счётчик обновлений на средней кнопке в рабочей области не показывается: он относится к панели подключения, а не к статистике.

### R6.1. Док прячется под оверлеями

Пока открыт любой диалог, bottom sheet или оверлей — на любой странице — док рабочей области уезжает вниз и не реагирует на нажатия. После закрытия возвращается.

### R7. Страница «Добавить»

Страница = только создание новой записи (`animeId == null`). Редактирование существующего тайтла остаётся push-экраном и работает как сейчас.

- У страницы своя инстанция `AddEditViewModel`, отдельная от push-экрана редактирования.
- Уход свайпом/доком со страницы сбрасывает черновик: страница всегда открывается чистой.
- После успешного сохранения рабочая область перелистывается на Главную.

### R8. Страницы «Кадр» и «Настройки»

Экраны переносятся в страницы без изменения содержимого. Кнопки «назад» в их шапках убираются (за возврат отвечают Back и док). Промо «подключить ИИ» в Кадре перелистывает на страницу Настроек вместо `navigateToSettings()`.

Внутренний пейджер Кадра (Аниме ↔ Фильмы) сохраняется и работает цепочкой: на краю внутреннего пейджера жест передаётся внешнему.

### R9. Dev-флаг

Вся новая навигация живёт под ключом `DevPreferencesKeys.SELECT_DOCK_NAVIGATION` (отсутствие ключа = ВЫКЛ). При выключенном флаге приложение ведёт себя ровно как сегодня: старый док, старые маршруты, свайпы на карточках, статистика-шторка.

## User-visible behavior

- Свайп по главной больше не «лайкает» и не удаляет — он листает разделы.
- Долгое удержание карточки — новый жест, ему нужно обучение: при первом показе меню даём тактильный отклик (`performHaptic(view, "light")`) в момент срабатывания удержания.
- Переходы между разделами перестают быть «открытием окна» и становятся перелистыванием с глубиной.

## Domain rules

Новых доменных понятий не вводится. Появляется одно UI-понятие:

- **Workspace page** — раздел корневой рабочей области. Перечисление из пяти значений с фиксированным порядком; порядок — часть контракта (индекс = позиция в пейджере и в доке).

## Functional requirements

| ID | Требование |
|---|---|
| F1 | Пейджер из 5 страниц, стартовая — Главная (индекс 2) |
| F2 | Тап по сегменту дока анимированно листает к соответствующей странице |
| F3 | Свайп между страницами применяет «наезд» (R3) |
| F4 | Back с не-главной страницы листает на Главную; с Главной — выход |
| F5 | Долгое удержание карточки открывает модальное меню (R5) |
| F6 | Свайпы `SwipeToDismissBox` на карточках не срабатывают при включённом флаге |
| F7 | Статистика рендерится страницей (R6) |
| F8 | Страница «Добавить» использует отдельную VM и сбрасывает черновик при уходе |
| F9 | После сохранения на странице «Добавить» пейджер листает на Главную |
| F10 | Кадр и Настройки рендерятся страницами без кнопок «назад» |
| F11 | Details и AddEdit-по-id открываются push-экранами поверх рабочей области |
| F12 | Диплинк из уведомления (`ACTION_OPEN_ANIME`) продолжает открывать Details поверх рабочей области |
| F13 | Флаг выключен → поведение идентично текущему |

## Non-functional requirements

| ID | Требование |
|---|---|
| N1 | Стекло дока: живое в покое, статичная заливка на время жеста/анимации; перехода между режимами не видно |
| N2 | Док не должен «схлопываться» в плоскую заливку после переходов (известный баг инвалидации `layerBackdrop`) |
| N3 | Соседние страницы предрендерятся (`beyondViewportPageCount = 1`), иначе «наезд» показывает пустой кадр |
| N4 | Свайп между страницами держит 60 fps на устройстве разработчика; проверяется существующим `FpsOverlay` |
| N5 | Математика «наезда» — чистая функция, покрытая unit-тестами |

## Compatibility and migration constraints

- Данных миграция не касается.
- Маршруты `SettingsRoute` и `InspectRoute` сохраняются в графе, пока жив флаг (нужны для выключенного состояния).
- `AddEditRoute` сохраняется навсегда — это путь редактирования по id.
- Shared-element переходы иконок дока исчезают при включённом флаге (у ключей не остаётся источника). Это принятая потеря, а не регрессия.

## Failure and fallback behavior

- Ошибка сохранения на странице «Добавить» оставляет пользователя на странице с черновиком (существующее поведение `AddEditEffect.ShowError`).
- Если страница «Кадр» не может отработать (нет ИИ-провайдера), она показывает существующий промо-блок; навигация не блокируется.
- Выделение карточки снимается принудительно, если запись исчезла из списка (удалена, отфильтрована).

## Out of scope

- Редизайн содержимого статистики (только форма подачи).
- Изменение верхнего дока (сортировка / уведомления / фильтр типа) — остаётся элементом страницы Главная.
- Плавающая кнопка поиска — остаётся элементом страницы Главная.
- Отказ от подтверждающих шторок в пользу undo.
- Перенос Details в рабочую область.
- Удаление dev-флага и старой навигации (отдельная задача после обкатки).

## Acceptance criteria

- [ ] A1. При включённом флаге корень приложения — рабочая область из 4 страниц в порядке Кадр · Главная · Добавить · Настройки, старт на Главной.
- [ ] A2. Свайп и тап по доку перемещают между страницами; активный сегмент дока всегда соответствует видимой странице.
- [ ] A3. Переход выглядит наездом: нижняя страница углубляется и параллаксит, верхняя едет полностью и рисуется поверх.
- [ ] A4. Back с любой не-главной страницы возвращает на Главную; с Главной закрывает приложение.
- [ ] A5. Горизонтальный свайп по карточке листает страницы, а не открывает избранное/удаление.
- [ ] A6. Долгое удержание карточки поднимает её, блюрит и затемняет фон, показывает четыре кнопки; состояние держится после отпускания пальца.
- [ ] A7. Пока карточка выделена, скролл списка, свайп страниц и док не реагируют; тап по пустому месту снимает выделение.
- [ ] A8. Карточка у нижнего края экрана подъезжает вверх так, что весь ряд кнопок виден над доком.
- [ ] A9. Звезда и мусорка открывают существующие шторки подтверждения; карандаш и i открывают AddEdit и Details.
- [ ] A10. Статистика открывается шторкой по средней кнопке верхнего дока; панель подключения открывается пунктом «Синхронизация» в настройках; обе работают как раньше.
- [ ] A10.1. Любой диалог, шторка или оверлей прячет док; после закрытия док возвращается и остаётся стеклянным.
- [ ] A11. Страница «Добавить» открывается чистой после ухода свайпом; после сохранения рабочая область оказывается на Главной, запись видна в списке.
- [ ] A12. Редактирование по карандашу открывает push-экран и не затирает черновик страницы «Добавить».
- [ ] A13. Кадр и Настройки работают страницами; промо «подключить ИИ» перелистывает на Настройки.
- [ ] A14. Док остаётся стеклянным после многократных переходов (не «плоским»).
- [ ] A15. При выключенном флаге всё поведение идентично текущему релизу.

## Test seams

- `WorkspacePage` — перечисление с индексами: резолв «Back → Главная», «страница ↔ индекс дока» тестируется без Compose.
- Трансформация «наезда» — чистая функция `(pageOffset: Float) -> PageTransform(scale, translationXFraction, dimAlpha, corner)`; таблица значений покрывается unit-тестами.
- Правило размещения выделенной карточки — чистая функция `(cardTop, cardHeight, menuHeight, viewportHeight, dockInset) -> liftPx`; покрывается unit-тестами.
- Остальное (жесты, стекло, fps) — только ручная проверка на устройстве.
