# TICKET-01: Исход резолва по каждому источнику в логе

## Status

DONE

## Objective

Сделать отказ резолва наблюдаемым: по логу одного запуска видно, чем закончился каждый из
четырёх RU-источников и на какой ступени он остановился.

## User or system value

Сейчас `AnimeGoSource` и `AniLibriaSource` при пустом результате не пишут ничего, а
`SourceEngine.safeResolve` логирует только падение и таймаут. Диагностика отказа требует
сопоставления сырых HTTP-строк Ktor вручную — так был потерян день на разбор этого же бага.
Без этого тикета ни один следующий не проверяется на устройстве.

—

## Scope

- `SourceEngine.safeResolve` — логировать исход каждой ветки: имя, число хостеров, число
  играбельных видео, длительность.
- `AniLibriaSource.resolveEpisode` — лог при пустом результате с указанием, что не сошлось
  (релиз не найден / сезон не опознан / серия за пределами релиза).
- `AnimeGoSource.resolveEpisode` — лог при пустом результате.
- `SeasonEpisodesResolver` строка 62 — добавить в лог `source` и признак наличия `title`
  у каждой строки сезона: `S2=13(AniList,titled)` вместо `S2=13`.

## Out of scope

- Изменение поведения резолва.
- Телеметрия и отправка логов куда-либо.
- Формат логов Ktor.

## Risks

- Легко случайно поменять поведение, вставляя логи в цепочки `?:` и `takeIf`. Диффы держать
  минимальными, логику не трогать.
- Шум в логе: писать исход одной строкой на источник, не на каждую ступень.

## Implementation notes

Четыре точки, все — только логи.

1. **`SourceEngine.safeResolve`** — исход каждой ветки одной строкой:
   `"$label → N hoster(s), M playable video(s), Tms"`. Играбельность считается тем же
   предикатом `isPlayableVetroVideoUrl`, что и финальная нормализация, но ДО неё — иначе
   не видно, что источник вернул хостер без единого пригодного URL (ровно случай jut.su).
   Ветка таймаута и ветка падения сохранены как были.

2. **`AniLibriaSource.resolveEpisode`** — цепочка `?: return emptyList()` разложена на два
   явных отказа: «релиз не сопоставлен» (с номером сезона и сезонным названием в строке)
   и «релиз не загрузился». Раньше оба молчали.

3. **`AnimeGoSource.resolveEpisode`** — три явных отказа: нет пригодного алиаса, нет матча
   по порогу (в строке печатается и порог, и набор алиасов), нет страницы плеера. Строка
   про матч сразу показывает главный дефект: в русский каталог уходит английский запрос.

4. **`SeasonEpisodesResolver`** — провенанс строки сезона:
   `S2=13(AniList,titled)` вместо `S2=13`. Признак `titled`/`untitled` показывает, сможет ли
   `SourceEngine` сузить поиск до сезона.

Логика резолва не тронута ни в одном файле: элвис-цепочки заменены на равнозначные
явные проверки на null, порядок вычислений сохранён.

## Review findings

Самопроверка диффа:

- **Эквивалентность поведения** — проверено построчно. `(a ?: b) ?: return` заменено на
  `val x = a ?: b; if (x == null) { log; return }`. Порядок и семантика те же.
- **Утечки в лог** — токенов, ключей и URL с авторизацией нет; печатаются названия аниме,
  алиасы, счётчики и длительности.
- **Шум** — одна строка на источник, не на ступень. `aliases=$localTitles` у AnimeGo
  ограничен тремя элементами по построению.
- **Архитектурный наблюдатель** — структурных изменений нет, границы не двигались, новых
  зависимостей не появилось. Долга не добавлено.
