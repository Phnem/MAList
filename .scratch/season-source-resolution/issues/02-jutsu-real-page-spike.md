Установить корневую причину того, что `JutSuEpisodePageParser` достаёт с реальной страницы
серии base64-конфиг плеера, но ноль видео-источников. Зафиксировать реальную разметку как
тестовый фикстур.

(`season-2/episode-2.html` = The Second Plate), и он воспроизвёлся на трёх сериях подряд.

## Implementation notes

### Что снято

`https://jut.su/shokugeki-no-souma/season-2/episode-2.html`, 2026-08-01, теми же заголовками,
что шлёт `VetroHttpSource.getText` + `scrapeEpisode` (UA `DEFAULT_UA`, `Accept-Language:
ru,en;q=0.9`, `Referer` = origin). HTTP 200, 67 711 байт.

Повторно снято с полноценной сессией: сначала страница тайтла с cookie-jar, затем страница
серии с `Referer` на тайтл и браузерным `Accept`. HTTP 200, 67 732 байта — **результат тот же**.

### Ответ

jut.su перешёл на новый плеер. В разметке присутствует признак:

```
jutsu_new_player = "yes";
```

В `<video>` приезжают четыре `<source>`, и у всех четырёх `src` — заглушка:

```html
<source src="https://gen.jut.su/templates/school/images/pixel.png?1080" type="video/mp4" label="1080p" res="1080"/>
<source src="https://gen.jut.su/templates/school/images/pixel.png?720"  type="video/mp4" label="720p"  res="720"/>
<source src="https://gen.jut.su/templates/school/images/pixel.png?480"  type="video/mp4" label="480p"  res="480" selected="true"/>
<source src="https://gen.jut.su/templates/school/images/pixel.png?360"  type="video/mp4" label="360p"  res="360"/>
```

Подстановка `type="video/mp4"` к PNG-заглушке — намеренная: разрешение закодировано в
query-параметре, а настоящий адрес подставляется на клиенте.

Во всей странице:

- вхождений `.mp4` — **0**
- вхождений `m3u8` — **0**
- хостов, кроме `gen.jut.su` (статика) и `jut.su`, — **нет**

Оба base64-блока разобраны:

- блок 0 (660 симв.) — конфиг плеера: `pview_season = "2"`, `pview_episode = "2"`,
  `video_intro_start = 174`, `video_intro_end = 264`, `video_outro_start = 1340`,
  `this_video_duration = 1512`, `jutsu_new_player = "yes"`. Ссылок на медиа нет.
- блок 1 (2 288 симв.) — список ачивок тайтла. К плееру отношения не имеет.

**Вывод: ноль видео — правильный разбор, а не дефект парсера.** Настоящих адресов в
получаемом нами HTML нет вообще. `isPlayableJutSuVideoUrl` отработал ровно как задумано,
отбраковав `pixel.*` по `PLACEHOLDER_STEMS` и по расширению `.png`.

### Гипотезы

| # | Гипотеза | Итог |
|---|---|---|
| 1 | Разметка отличается от синтетического фикстура | **ПОДТВЕРЖДЕНА** — теги есть, но это заглушки |
| 2 | `isPlayableJutSuVideoUrl` отбраковывает настоящие URL | **ОПРОВЕРГНУТА** — отбраковывать нечего, настоящих URL в HTML нет |
| 3 | `<source>` вообще нет в статическом HTML | **ЧАСТИЧНО** — теги присутствуют, но без пригодного `src` |

### Следствие для плана

TICKET-03 в исходной формулировке («вернуть извлечение, починив ступень 1») невыполним:
чинить нечего. jut.su перестал быть источником видео и остался источником таймскипов —
тайминги и длительность парсятся полноценно, `reference` строится.

Это меняет расстановку: вся нагрузка по видео переходит на Kodik, AniLibria и AnimeGo,
то есть на тикеты 04–07. TICKET-03 переведён в NEEDS_USER_DECISION.

## Deviations

- Planned: сохранить фикстур и написать **падающий** тест, который зеленеет в TICKET-03.
- Actual: написан **проходящий** регрессионный тест, пиннящий реальное поведение —
  ноль видео плюс валидный skip-reference.
- Reason: дефекта в парсере не оказалось. Падающий тест пришлось бы писать на несуществующее
  требование «извлечь URL, которых в документе нет».
- Consequence: TICKET-03 нельзя выполнить как написан; переведён в NEEDS_USER_DECISION.
- Follow-up: решение пользователя по jut.su (см. TICKET-03).

## Review findings

- Снимок сделан дважды, разными профилями запроса — результат воспроизводится, разовый сбой
  или гео-выдача исключены.
- Признак `reference=true` из лога устройства сходится со снимком: конфиг парсится в обоих
  случаях, значит снятая страница той же природы, что видит телефон. Риск «локальный HTML
  разошёлся с устройством», записанный в тикете, снят.
- Фикстур сокращён, но не отредактирован по смыслу: `<video>` и блок конфига перенесены
  дословно, удалены только вёрстка, реклама и блок ачивок.
- Утечек в репозиторий нет: фикстур не содержит ни токенов, ни ссылок на медиа.

Блокирующих замечаний нет.
