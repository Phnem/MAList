# TICKET-08: Трансляция номера сезона каталог → источник

## Status

DONE_WITH_DEVIATIONS

## Objective

Перестать отождествлять позицию сезона в цепочке франшизы AniList с номером сезона у сайта.
Транслировать номер перед подстановкой в URL и ключи, а при недоказуемой трансляции —
отдавать пусто, а не чужой сезон.

## User or system value

Лог: `jut.su/shokugeki-no-souma/season-6/episode-1.html → 404 → No sources … season=6`.

Каталог считает Totsuki Train Arc отдельным сезоном, поэтому у него S1..S6. У jut.su,
Kodik и AniLibria тот же тайтл разложен на 5 сезонов. Отсюда два разных отказа:

- **S6 → 404**: сезона с таким номером у источника нет.
- **S4 → 200, но чужой контент**: `season-4` на jut.su — это The Fourth Plate, а приложение
  называет S4 «Totsuki Train Arc».

Второй случай опаснее первого: он не отказ, а тихая подмена.

Дополнительно тем же дефектом заражено слияние: `mergeSeasonDiscovery` и
`mergeStreamingSeasons` сводят найденное у источников по номеру, приписывая число серий
чужому сезону каталога.

## Dependencies

TICKET-03, TICKET-05, TICKET-06, TICKET-07 — трансляция бессмысленна, пока источники
не умеют находить видео по правильному номеру.

## Scope

Новая чистая функция трансляции в `domain/seasons/`, лестница по убыванию точности:

1. **Совпадение по числу серий** — сопоставить цепочку каталога с раскладом сезонов
   источника (`DiscoveredSeason`, который jut.su и Kodik уже умеют отдавать через
   `findSeasons`) по числу серий; при однозначном сопоставлении номер известен точно.
2. **Перебор соседей в пределах расхождения длин цепочек** — если у каталога сезонов на N
   больше, кандидаты ограничены сдвигом 0..N; принимается только тот, чьё число серий
   сошлось.
3. **Тождество** — когда длины цепочек равны, номер каталога и есть номер источника.
4. **Отказ** — если ни одна ступень не доказала соответствие, источник получает пусто.

Плюс:

- `mergeSeasonDiscovery` / `mergeStreamingSeasons` — сливать по транслированному номеру.
- Решить, меняется ли содержимое `SeasonInfo`; если да — поднять
  `SeasonEpisodesEntry.CURRENT_SCHEMA` (сейчас 2), иначе оставить.

## Out of scope

- Переработка обхода франшизы в `SeasonEpisodesResolver`.
- UI-подпись сезонов.
- Кэш раскладов источников.

## Expected architecture impact

Закрывает п. 2.2 архитектурного обзора: перегруженный смысл `seasonNumber` разводится
на две величины. Трансляция общая, поэтому живёт в `domain/seasons/`, а не в источниках.

## Risks

- Число серий у источника и у каталога расходится штатно (залита половина сезона) —
  сопоставление обязано это допускать, иначе ступень 1 будет отказывать всегда.
- Ступень 2 при большом расхождении даёт много кандидатов; ограничить и не принимать
  неоднозначность.
- `findSeasons` стоит сетевых запросов; трансляция не должна дёргать его на каждую серию —
  использовать уже сохранённый расклад из `SeasonEpisodesStore`.

## Implementation notes

Новый чистый модуль `domain/seasons/SeasonIndexTranslation.kt`.

Ключевое наблюдение: связь между шкалами регулярна — **сезон источника есть склейка одного
или нескольких подряд идущих каталожных сезонов, и суммарное число серий сохраняется**.
Отсюда жадное сопоставление `alignSeasonScales`: идём по сезонам источника, набирая
каталожные, пока сумма не сойдётся ровно.

Для «Повар-боец Сома» каталог `[24,13,12,12,12,13]` против источника `[24,13,24,12,13]`
даёт `{1→1, 2→2, 3→3, 4→3, 5→4, 6→5}`:

- S6 → сезон 5 источника (искомый случай 404);
- S4 (Totsuki Train Arc) → сезон 3, а не 4 — тихая подмена закрыта.

`translateCatalogueSeason` — лестница: сопоставление по числу серий → тождество при равных
длинах цепочек → отказ. Недоказуемая трансляция не подменяется догадкой.

Применено в `mergeSeasonDiscovery`: раскладки разных источников сливаются по отдельности
(шкала у каждого своя), и число серий переносится только для сезонов источника, накрывающих
ровно один каталожный (`oneToOneSourceSeasons`). Сезон-склейка знает сумму по нескольким
каталожным сезонам — записать её в одну строку значит её завысить, поэтому такие пропускаются:
каталог здесь точнее. Когда шкалы не сцепились, поведение прежнее — слияние по номеру.

`CURRENT_SCHEMA` **не поднят**: состав полей `SeasonInfo` не изменился, изменилось только
то, в какую строку попадает число серий от источника. Уже сохранённые записи остаются
валидными и перетираются очередным обходом.

## Deviations

- Planned: транслировать номер и на резолве — в частности заменить
  `.getOrNull(seasonNumber - 1)` во франшизном пути AniLibria.
- Actual: трансляция применена только в слиянии раскладов.
- Reason: на резолве нужна ПОЛНАЯ цепочка сезонов каталога, а `SourceEngine` и источники
  получают единственный `SeasonInfo`. Прокидывание всей цепочки через `MediaGateway` →
  `SourceEngine` → четыре источника — самостоятельная работа, а не деталь этого тикета,
  и тикет прямо запрещает лезть в `findSeasons` на каждую серию.
- Consequence: индексная зависимость осталась в одном месте — франшизный путь AniLibria.
  Практический риск снижен тикетом 06: даже выбрав релиз по неверному индексу, AniLibria
  обязан подтвердить его через `releaseIdentifiesSelectedSeason`, то есть отдаст пусто,
  а не чужой сезон. Инвариант плана соблюдён.
- Follow-up: **TICKET-09** — прокинуть цепочку сезонов до источников и применить трансляцию
  на резолве (см. Deferred work в master plan).

Также не сделано: добавление `ONA` в `ANILIBRIA_SEASON_TYPES`, перенесённое сюда из
TICKET-06. Оно осмысленно только вместе с трансляцией на резолве и уходит в TICKET-09.

## Review findings

- **Догадки вместо доказательства** — закреплено тестами `unprovable alignment refuses
  instead of guessing`, `source longer than catalogue refuses`, `catalogue tail left
  uncovered refuses`, `zero and empty counts refuse`.
- **Завышение счётчика склейкой** — `glued source season is not one to one` фиксирует, что
  сезон 3 источника (24 серии, накрывает S3+S4 по 12) в `oneToOneSourceSeasons` не входит
  и в каталожную строку не переносится.
- **Обратная совместимость** — при несцепившихся шкалах ветка слияния идентична прежней;
  `StreamingSeasonRefreshTest` не потребовал правок и остаётся зелёным.
- **Разные источники не перемешиваются** — слияние идёт по группам `discovered.groupBy { source }`.
- **Чистота** — модуль без ввода-вывода и без зависимости на Android; сети не добавилось,
  `findSeasons` на резолве не дёргается.

Блокирующих замечаний нет.
