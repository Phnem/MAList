# MOVIE/SERIES automatic provider infrastructure

## Problem

MOVIE/SERIES воспроизведение сейчас возможно только если пользователь уже владеет Jellyfin, Emby,
WebDAV/Nextcloud, S3 или прямой ссылкой. Инфраструктуры, сопоставимой с ANIME-каскадом, нет:

- `PlaybackRoutingPolicy` схлопывает MOVIE и SERIES в единственный маршрут `DirectOnly`, теряя
  различие RU/EN, хотя `AppLanguage` доходит до `PlaybackRequest`;
- `MovieSeriesSourceResult` имеет три состояния (`Found`/`NoMatch`/`NotConfigured`) и не различает
  таймаут, блокировку, rate-limit, некорректный ответ и неподдерживаемый запрос;
- нет слоя ID-first сопоставления: правила точности реализованы внутри Jellyfin/Emby адаптера и не
  переиспользуются;
- ранжирование (`rankVideosForResolution`) учитывает только разрешение и содержит захардкоженный
  `reliabilityRank()` с именем конкретного хоста;
- нет памяти о здоровье провайдера: неотвечающий источник каждый раз выжидает полный таймаут;
- нет UI выбора между несколькими вариантами воспроизведения;
- добавление источника требует изменения кода и пересборки.

## Desired outcome

MOVIE/SERIES получают собственную provider-инфраструктуру: единый contract с capabilities,
раздельные RU/EN каскады, ID-first сопоставление, множественные кандидаты, ranking, provider health,
ограниченные таймауты, экран выбора источника — и возможность подключить совместимый сервис
конфигурацией без пересборки.

## Current behavior

- `SourceEngine.resolve` маршрутизирует через `PlaybackRoutingPolicy`; MOVIE/SERIES → `DirectOnly` →
  `resolveMovieSeriesSources` с общим таймаутом 20 c на источник.
- `runPlaybackProviderCascade` уже отказоустойчив: `supervisorScope`, падение одного источника не
  отменяет соседей, `CancellationException` пробрасывается, фиксируются `failed`/`timedOut`/`elapsedMs`.
- Результаты нормализуются в `VetroHoster`/`VetroVideo` до плеера и загрузчика.
- `VetroVideo.downloadAllowed` по умолчанию `false`.
- IMDb ID существует только в `KinopoiskDto`/`KinopoiskDetails`, до `Anime` и БД не доходит.

## Required behavior

1. Единый contract automatic/personal провайдеров с объявляемыми capabilities.
2. Раздельные RU и EN каскады; локаль задаёт приоритет, но язык выбирается вручную.
3. Приоритет идентификации: TMDB ID → IMDb ID → Kinopoisk ID → нормализованный title + year;
   для SERIES дополнительно season/episode. Конфликтующий ID никогда не выбирается автоматически.
4. Типизированный исход провайдера: `FOUND`, `NOT_FOUND`, `TEMPORARY_ERROR`, `BLOCKED`,
   `RATE_LIMITED`, `INVALID_RESPONSE`, `UNSUPPORTED`, `NOT_CONFIGURED`.
5. Каскад собирает несколько кандидатов, а не останавливается на первом.
6. Ranking учитывает точность ID-совпадения, язык, качество, прямоту потока и здоровье провайдера.
7. Provider health персистится и влияет на порядок и на пропуск заведомо мёртвых источников.
8. У каждого сетевого провайдера ограниченный таймаут; каскад быстро идёт дальше.
9. Пользователь может добавить источник Vetro-манифестом или импортом Stremio-аддона, включить,
   выключить, проверить, обновить и удалить его в настройках.
10. Экран выбора источника для MOVIE/SERIES показывает варианты с языком, провайдером и качеством.
11. IMDb ID доходит до доменной модели и `PlaybackIdentity`.

## User-visible behavior

- Для фильма/сериала доступен экран «Смотреть» с разделами по языку и разделом «Мои источники».
- При нескольких вариантах пользователь выбирает провайдера/перевод/качество.
- Падение одного провайдера не превращается в общую ошибку, если другой нашёл поток.
- `Настройки → Источники видео → Добавить источник` принимает ссылку на манифест или файл.
- Некорректный/недоступный манифест сообщает причину и не сохраняется как рабочий.

## Domain rules

- Metadata provider и playback provider — разные роли; знание об эпизоде не подразумевает поток.
- Провайдер объявляет `downloadAllowed` только на основании явного разрешения, не по форме URL.
- Released-only семантика эпизодов сохраняется: невышедший эпизод не является playable.
- «Неизвестно» не превращается в «нет»: отсутствующий ID — не совпадение, а отсутствие данных.
- Пользовательский манифест описывает структурный API; он не является механизмом извлечения
  потоков со страниц и не может расширить права за пределы глобальной политики.

## Functional requirements

- Contract: `id`, `capabilities`, `suspend resolve(request): ProviderResolution`.
- Capabilities: `MOVIE`, `SERIES`, `RU`, `EN`, `DIRECT`, `HLS`, `SUBTITLES`, `MULTI_AUDIO`,
  `DOWNLOAD`, `TMDB_ID`, `IMDB_ID`, `KINOPOISK_ID`.
- Провайдер, не объявивший применимую capability, не вызывается по сети.
- Vetro-манифест: версионированный декларативный JSON, шаблоны путей с подстановками, JSON-pointer
  маппинг ответа, цепочки из нескольких запросов (resolve id → запрос потока), пагинация/повтор с
  backoff, несколько auth-схем (header/query/bearer). Остаётся декларативным: без исполнения кода,
  без HTML-scraping, без разворачивания iframe, без обхода анти-бот защиты — это не сужение, а
  структурное свойство формата, отделяющее его от plugin-рантайма.
- Stremio-импорт: `/manifest.json` → внутренний дескриптор; запросы `/stream/{type}/{id}.json`;
  id фильма `tt…`, id эпизода `tt…:{season}:{episode}`; принимается только `url` c http(s);
  `infoHash`/`nzbUrl`/архивы/`ytId`/`externalUrl` отклоняются; манифест с `behaviorHints.p2p`
  отклоняется при импорте.
- Health: `lastSuccess`, `lastFailure`, `consecutiveFailures`, `averageLatency`,
  `temporaryDisabledUntil`; временное отключение с экспоненциальным восстановлением, без вечного бана.
- Секреты пользовательских источников — в существующем encrypted store через `credentialRef`.

## Non-functional requirements

- Ограниченная параллельность каскада; без неконтролируемого fan-out.
- ANIME-пути (`AniLibria`, `AnimeGo`, `AnimeHeaven`, `jut.su`, `Kodik`, anime season discovery)
  сохраняют текущее поведение.
- Никаких секретов в Git, логах, исключениях, фикстурах, WorkManager input, ViewModel/UI state.
- `Authorization` не уходит на другой origin; credentialed redirects не следуются.
- Существующие 416 app + 55 core/network тестов остаются зелёными.

## Compatibility and migration constraints

- Добавление `imdb_id` в схему `Anime` требует прямой миграции; старые строки остаются валидными
  с `null`.
- `VetroVideo`/`VetroHoster` остаются единственной моделью для плеера и загрузчика.
- Существующие настройки WebDAV/Jellyfin/Emby и их сохранённые секреты продолжают работать.
- Global download default-deny (`a5e6500`) не ослабляется.

## Failure and fallback behavior

- `A error → B not found → C found` даёт результат C.
- Все провайдеры не нашли → `NoMatch`; все упали → `Failure`; ни один не применим/не настроен →
  `NotConfigured`.
- `CancellationException` всегда пробрасывается.
- Таймаут провайдера не блокирует каскад; он засчитывается в health.
- Невалидный ответ пользовательского источника — `INVALID_RESPONSE`, а не крэш.

## Out of scope

- Collaps, HDVB, Filmix, Rezka, VidSrc, VidLink, Videasy, Embed.su, AutoEmbed и аналогичные
  сервисы нелицензионной раздачи; расширение `KodikSource` на MOVIE/SERIES.
- Обход DRM, CAPTCHA, Cloudflare, анти-бот механизмов и access control.
- HTML-scraping, regex-извлечение потоков, исполнение JS, разворачивание iframe в формате манифеста.
- Локальный plugin-рантайм с исполнением стороннего кода для получения потоков (даже в sandbox).
  Отклонено пользователем 2026-08-10: на практике такой рантайм в экосистемах Stremio/Kodi становится
  основным способом доставки пиратских скрейперов через community-плагины. Произвольная логика
  получения потока допускается только на стороне сервера через Stremio-addon транспорт.
- Torrent/P2P, usenet, распаковка архивов.
- Поставка готовых конфигураций, указывающих на инфринг-сервисы.
- Plex, VK, RUTUBE (отложены предыдущим этапом).
- DASH offline download.
- Internet Archive / Wikimedia Commons как automatic-провайдеры (TICKET-11) — понижено до deferred,
  не входит в требуемый объём этого этапа.

## Acceptance criteria

- MOVIE/SERIES резолвятся раздельными RU/EN каскадами; ANIME-поведение не изменилось.
- Провайдер возвращает типизированный исход; каскад различает все состояния раздела 16 задания.
- ID-first matching покрыт тестами, включая отказ при конфликтующих ID.
- Каскад возвращает несколько кандидатов; ranking детерминирован и покрыт тестами.
- Health переживает перезапуск и пропускает временно отключённый источник без сетевого ожидания.
- Vetro-манифест и Stremio-манифест подключаются из настроек и доходят до плеера.
- Экран выбора источника показывает язык/провайдера/качество и запускает выбранный поток.
- IMDb ID персистится и участвует в идентификации.
- Полные unit-суиты и debug-сборка проходят.

## Open questions

- SAFE_DEFAULT: хранилище health — файловое, как существующие кэши проекта. Меняется на БД позже
  без изменения интерфейса.
- SAFE_DEFAULT: ограниченная параллельность каскада — не более 4 одновременных провайдеров.
- DEFERRED: Internet Archive / Wikimedia как automatic-провайдеры (TICKET-11) — не входят в
  требуемый объём этого этапа; делаются только по отдельному запросу.
- DEFERRED: миграция `StreamingSeasonDiscovery` на общий механизм — только если каскад в неё упрётся.
- DECIDED: локальный plugin-рантайм с исполнением стороннего кода для получения потоков не строится
  ни в каком тикете этого этапа; расширяемость пользовательских источников закрывается декларативным
  манифестом (TICKET-07) и Stremio-импортом (TICKET-08).
