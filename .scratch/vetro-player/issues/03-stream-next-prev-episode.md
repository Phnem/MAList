# TICKET-03: Рабочие кнопки следующей и предыдущей серии в стриминговом плеере

## Status

PENDING

## Objective

Кнопки следующей и предыдущей серии в стриминговом плеере переключают серию, резолвя ссылку внутри плеера, без выхода на экран выбора.

## User or system value

Пункт 2 списка.

## Dependencies

**Блокируется TICKET-02** — оба правят `StreamPlayerSurface.kt`.

## Scope

- `media/ui/StreamPlayerSurface.kt` (`:237-238`) — сейчас передаёт `hasPrev = false, hasNext = false` литералами.
- `media/ui/StreamPlayerActivity.kt` — контекст серии (`EXTRA_SEASON`, `EXTRA_EPISODE`, `EXTRA_SEASON_JSON`) читается один раз в `onCreate` и лежит в неизменяемых локальных `val`. Для переключения нужно наблюдаемое состояние текущей серии (находка архобзора).
- Резолв ссылок соседней серии — существующим путём (`StreamWatchViewModel` уже это умеет), за узким интерфейсом «дай ссылки для (season, episode)».

**Решение интервью (D-3):** резолв **внутри плеера**, не возврат к экрану выбора и не предзагрузка.

**Правило из спеки, не нарушать:** «есть соседняя серия по номеру» и «удалось зарезолвить ссылку» — **разные** состояния. Неудачный резолв нельзя показывать как «серии нет».

`PlayerControls` менять не требуется: `hasPrev`/`hasNext` у него уже есть, недоделана только их передача. Интерфейс был спроектирован верно.

## Out of scope

Локальный плеер — там переключение работает через плейлист ExoPlayer, трогать нечего. Предзагрузка соседних серий (отклонена на интервью). Переезд `PlayerControls` в общий пакет (FOLLOW_UP архобзора).

## Acceptance criteria

- [ ] Кнопки следующей и предыдущей серии переключают серию в стриминговом плеере.
- [ ] На последней серии сезона «следующая» неактивна, на первой «предыдущая» неактивна.
- [ ] На время резолва виден индикатор; текущее воспроизведение не рвётся, пока новая ссылка не готова.
- [ ] Ошибка резолва — сообщение, текущая серия продолжает играть; пустого экрана нет.
- [ ] Прогресс просмотра пишется для правильной серии после переключения.
- [ ] Локальный плеер не изменился.
- [ ] Вычисление «есть ли соседняя серия» — чистая функция, покрытая unit-тестом: первая серия, последняя, единственная, неизвестное общее число.

## Verification plan

`.\gradlew.bat :app:testDebugUnitTest` — тесты границ диапазона (пишутся первыми). `.\gradlew.bat :app:compileDebugKotlin`.

Реальное переключение с резолвом источника подтверждает пользователь: сеть и воспроизведение в этой сессии не проверить.

## TDD classification

REQUIRED — граничные условия диапазона серий детерминированы, и ошибка здесь даёт либо мёртвую кнопку, либо переход на несуществующую серию.

## Expected architecture impact

Контекст текущей серии стримингового плеера становится наблюдаемым состоянием вместо значений, прочитанных один раз. Появляется узкий интерфейс резолва соседней серии; UI о источниках не знает.

## Risks

- Самый крупный тикет пакета: меняется модель состояния активности, а не только вёрстка.
- Гонка: быстрые нажатия «следующая» подряд могут запустить несколько резолвов. Отбивать так же, как отбивалось повторное добавление в TICKET-08 прогона `vetro-todo`.
- Прогресс просмотра привязан к (`animeId`, `season`, `episode`) — после переключения он обязан писаться для новой серии, иначе просмотр запишется не туда.
- Неизвестное общее число серий не должно превращаться в «серий нет» (правило спеки).
