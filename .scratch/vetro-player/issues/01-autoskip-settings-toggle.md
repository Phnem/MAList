# TICKET-01: Переключатель автопропуска в настройках

## Status

DONE (фактическую перемотку на видео подтверждает пользователь — см. Completion evidence)

## Objective

В настройках появляется переключатель автопропуска, который пишет `AUTO_SKIP_KEY`, — и уже построенный механизм автопропуска наконец становится достижимым.

## User or system value

Пункт 1 списка. Сегодня весь механизм (AniSkip-провайдер, перемотка в обоих плеерах, ручная кнопка) существует, но у настройки **ноль писателей**, дефолт `false`, и включить её нечем. Это самый дешёвый тикет пакета с самой высокой отдачей: одна строка настроек оживляет готовую функцию.

## Dependencies

Нет — можно начинать сразу.

## Scope

- `ui/settings/` — строка с переключателем (`SettingsScreen` / `SettingsSheets`, по образцу соседних пунктов).
- Запись `LocalPlayerViewModel.AUTO_SKIP_KEY` в DataStore `named("settings")`.
- Строки локализации — **не** в `UiStrings` (см. Risks).

Читатели уже есть и менять их не требуется: `LocalPlayerViewModel:61`, `StreamPlayerActivity:124`, `DownloadedPlayerActivity:84`.

По решению D-1 переключатель охватывает **все** виды сегментов (`OPENING`, `ENDING`, `RECAP`, `MIXED`) — ровно так код и работает сегодня, логику плееров трогать не нужно.

## Out of scope

Механизм определения сегментов. Логика перемотки в плеерах. Ручная кнопка пропуска. Отдельные переключатели по видам сегментов (отклонено на интервью).

## Acceptance criteria

- [ ] В настройках есть переключатель автопропуска.
- [ ] Переключение пишет `AUTO_SKIP_KEY` в DataStore `named("settings")` — тот самый ключ, который читают три активности.
- [ ] Состояние переживает перезапуск приложения.
- [ ] При включённом автопропуске плеер перематывает сегмент, ручная кнопка не показывается.
- [ ] При выключенном — поведение ровно как сегодня (ручная кнопка).
- [ ] Новые строки не добавлены в `UiStrings`.

## Verification plan

`.\gradlew.bat :app:compileDebugKotlin`. Фактическую перемотку на реальном видео подтверждает пользователь — устройства в сессии нет, и заявлять эту проверку выполненной я не буду.

Проверить, что ключ совпадает **посимвольно** с `local_player_auto_skip`: писать в другой ключ — значит оставить механизм ровно таким же мёртвым, только с переключателем.

## TDD classification

NOT_NEEDED — строка настроек и запись в DataStore. Альтернативная верификация: компиляция плюс сверка имени ключа с тремя существующими читателями.

## Expected architecture impact

У существующего ключа появляется писатель. Новых абстракций не вводится.

## Risks

- **Разъехавшийся ключ.** Опечатка в имени = функция остаётся недостижимой, а внешне всё выглядит рабочим. Отсюда критерий про посимвольную сверку.
- **`UiStrings`.** Больше 254 полей роняет release-сборку (`VerifyError` в `clinit`), в debug не воспроизводится. Новые строки класть в отдельный объект.

## Implementation notes

- `utils/Localization.kt`: `PlayerSettingsStrings` + `getPlayerSettingsStrings(lang)` — **отдельный объект**, по образцу `CollectionEnrichmentStrings`/`WebLinksStrings`. В `UiStrings` не добавлено ничего.
- `SettingsUiState`: `autoSkipSegments: Boolean = false`.
- `SettingsViewModel`: чтение в маппинге состояния и `setAutoSkipSegments(enabled)`.
- `SettingsScreen`: строка с `IosSwitch` в основной пользовательской группе (рядом с «Облако», «Обогащение», «ИИ», «Связь»), иконка `Icons.Filled.FastForward`, с гаптикой как у соседей.

**Ключ переиспользован напрямую:** `settingsDataStore.edit { it[LocalPlayerViewModel.AUTO_SKIP_KEY] = enabled }`. Вторую строковую константу не заводил — это полностью снимает риск «разъехавшегося ключа», записанный в Risks: разъехаться нечему, объявление одно.

Подтверждено, что это тот же экземпляр DataStore: `SettingsViewModel` получает `settingsDataStore = get(named("settings"))` (`di/viewModelModule.kt:63`), плееры читают из него же.

## Deviations

Отступлений нет.

## Review findings

- **Ключ — единственное объявление.** `grep AUTO_SKIP_KEY` показывает семь ссылок на одну константу из `LocalPlayerViewModel:112`: три читателя (`LocalPlayerViewModel`, `StreamPlayerActivity`, `DownloadedPlayerActivity`) и теперь писатель в `SettingsViewModel`. Дублирующей строки `"local_player_auto_skip"` в коде нет.
- **`UiStrings` не тронут** — новые строки в отдельном `PlayerSettingsStrings`, release-ограничение в 254 поля не задето.
- **Логика плееров не менялась** — по решению D-1 переключатель охватывает все виды сегментов, ровно как код уже работает. Правка ограничена настройками.
- **Подпись переключателя честная**: сказано, что пропускаются опенинг, эндинг и рекап, а не только опенинг. Обещать в UI меньше, чем делает код, — это ловушка для пользователя.
- **Размещение** — в основной пользовательской группе, а не в dev-секции: функция пользовательская.
- Блокирующих замечаний нет.
