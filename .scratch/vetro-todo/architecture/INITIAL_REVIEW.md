# Архитектурный обзор перед декомпозицией — vetro-todo

Область: только те модули, которых касаются 10 принятых пунктов. Это вход для планирования тикетов, а не заявка на рефакторинг репозитория.

## 1. Какие границы помогают, какие мешают

**Помогает.** `OverlayThemeTokens` — единая точка для цветов оверлеев; `MotionTokens`/`IosDesign` — для пружин. Три «цветных» пункта (4, 5, 6) ложатся туда без новых абстракций.

**Мешает.** Золотой цвет избранного существует в двух несвязанных местах: токеном `FavoriteCardBorder = IconAccountYellow` и *захардкоженным литералом* `Color(0xFFFFD600)` прямо в `HomeComponents.kt:741`. Именно поэтому рамка и заливка свайпа разъехались — это и есть дефект из п.6. Чинить только рамку значит оставить причину на месте.

**Мешает.** `AddFromApiUseCase` смешивает оркестрацию I/O (скачивание постера, detail-запрос к Shikimori) с сохранением, и не имеет ни одного шва, куда встал бы предикат дубликата. Под п.9 нужен вынос правила «это дубликат» в чистую функцию — иначе его нечем покрыть тестом.

## 2. Нужен ли префакторинг до реализации

Отдельного префакторинг-тикета не нужно. Два выноса делаются внутри своих тикетов и там же проверяются:

- золотой → общий токен (внутри TICKET-05);
- правило дубликата → чистая функция (внутри TICKET-08).

## 3. Какие модули обязаны остаться стабильными

`:core:network` (DTO и маппинг источников), `data/models/Anime.kt`, SQLDelight-миграции. По решению интервью п.8 — только представление, схема не трогается. Свежая миграция `12.sqm` уже в дереве от предыдущей работы — не переписывать.

## 4. Где прятать сложность

- Правило дубликата и схлопывание списка — за одной функцией с узкой сигнатурой (`List<Anime> -> List<Anime>` + предикат), UI и use-case о деталях сравнения не знают.
- Оптимистичное состояние кнопки «добавить» — во ViewModel, отдельным множеством «добавляется сейчас», а не выводом из БД. Сейчас кнопка читает состояние БД, и это ровно причина отката.

## 5. Какие публичные интерфейсы поедут

`AddFromApiUseCase.invoke` — вернёт результат с признаком «уже есть», а не просто `Result<Unit>`. Один вызывающий (`HomeViewModel`). Больше ничего публичного менять не требуется.
