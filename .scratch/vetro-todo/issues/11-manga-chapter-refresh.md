# TICKET-11: Фоновое обновление оглавлений манги

## Status

PENDING — заведён из TICKET-09 по его же правилу «остановиться и вынести добычу данных отдельным тикетом».

## Objective

Оглавления привязанных к источнику тайтлов манги обновляются фоном, а не только в момент, когда пользователь открывает вкладку «Главы».

## User or system value

Без этого метка «вышли новые главы» на карточке главного экрана (TICKET-09) узнаёт о новых главах с задержкой: она считает по файловому кэшу `MangaChapterCacheStore`, а кэш пополняется единственным писателем — `MangaLibraryViewModel.loadChapters`, то есть открытием вкладки.

Аниме этой проблемы не имеет: у него есть `BatchEpisodeCheckUseCase` + `AnimeUpdateWorker`, которые ходят по коллекции фоном. **У манги аналога нет вовсе** — установлено при реализации TICKET-09.

## Scope

- Фоновый проход по `MangaBindingStore.flow` (только тайтлы с подтверждённой привязкой — без неё источник неизвестен).
- `MangaSourceEngine.chapters(item)` для каждого, результат в `MangaChapterCacheStore.put(...)`.
- Периодичность и условия запуска — по образцу `AnimeUpdateWorker` (WorkManager, сеть обязательна).
- Троттлинг источников: MangaDex и Remanga — публичные API с лимитами, ходить по всей коллекции без пауз нельзя. Образец — `AiThrottlePolicy` из Collection Enrichment.

## Out of scope

- Отрисовка прогресса и метки новых глав на карточке — сделано в TICKET-09.
- Системные уведомления о новых главах (у аниме они есть; для манги — отдельное решение пользователя).
- Движок источников манги: новых источников не добавляем.

## Acceptance criteria

- [ ] Оглавления привязанных тайтлов обновляются без открытия вкладки «Главы».
- [ ] Проход не ходит в источник чаще, чем позволяет TTL кэша, и делает паузы между тайтлами.
- [ ] Пустой ответ источника не затирает уже накопленное оглавление (правило `MangaChapterCacheStore`).
- [ ] Тайтлы без привязки не трогаются вовсе.

## TDD classification

RECOMMENDED — отбор «кого пора обновлять» (TTL, наличие привязки) чистая функция; сетевой проход нет.

## Risks

- Проход по всей коллекции может упереться в лимиты источников — главный риск, ради него троттлинг в области.
- Кэш ограничен `MAX_ENTRIES = 60`: фоновый проход по большой коллекции будет вытеснять сам себя. Возможно, придётся поднять потолок или хранить только счётчик глав.
