## Implementation notes

**Что было блёклым — установлено точно.** Обе палитры строились как «брендовый оранжевый + нейтралы», и нейтралы рядом с `#E85002` читались не как другой пункт, а как выключенный:

| Место | Пункт | Было |
|---|---|---|
| Сортировка (`glass.kt`) | Рейтинг | `#E85002` |
| | Эпизоды | `#FFB067` бледный персик |
| | **По названию** | `#A7A7A7` **серый** |
| | **По жанрам** | `#D9C3AB` **бежевый** |
| Категории (`FormatCategoryTilesSection.kt`, `SharedComponents.kt`) | Anime | `#E85002` |
| | Movies | `#8A8A8E` **серый** |
| | Series | `#D9C3AB` **бежевый** |

**Новый ряд** — токены `OverlayThemeTokens.SortAccent{Primary,Secondary,Tertiary,Quaternary}`: `#E85002` → `#FF7A1A` → `#FF9500` → `#FFB300`. Внутри брендового семейства (оранжевый → янтарь), новых оттенков не введено.

Золотой `#FFD600` намеренно **не** задействован: он закреплён за избранным (`FavoriteCardBorder`, TICKET-05), смешивать роли нельзя.

**Попутно устранено дублирование** (файлы правились всё равно, палитры разъехались бы снова):

- `SortOption.getAccentColor()` и локальные `accentRating/...` в `SortFilterOverlay` были двумя копиями одного списка литералов — теперь оба читают токены, `sortAccent()` делегирует в `getAccentColor()`.
- Список категорий продублирован в `FormatCategoryTilesSection.kt:97` и `SharedComponents.kt:176` — обе копии переведены на те же токены.

## Deviations

- **Планировалось:** «сделать насыщеннее».
- **Сделано:** конкретный ряд `#E85002 / #FF7A1A / #FF9500 / #FFB300`.
- **Причина:** критерий «достаточно ли насыщенно» вкусовой, а спека прямо запрещает вводить оттенки вне брендовой палитры. Ряд выбран так, чтобы пункты остались различимыми и при этом ни один не читался нейтралом. Это решение за пользователя, и оно помечено как ожидающее его оценки — а не выдано за согласованное.
- **Последствия:** оттенки меняются одной правкой четырёх токенов в `OverlayThemeTokens`, по месту их больше нет.
- **Follow-up:** не требуется, если пользователя ряд устраивает.

## Review findings

- **Контраст кнопки «Применить» — исправлен, иначе правка внесла бы регрессию.** Цвет текста выбирался сравнением `applyAccent == accentRating`: чёрный только на брендовом, белый на всех остальных. С прежними бледными акцентами белый и так читался посредственно, а с новыми янтарными стал бы нечитаем. Переведено на `luminance() > 0.2f`; порог подобран так, что `#E85002` (яркость ≈ 0.23) по-прежнему получает чёрный текст — поведение для рейтинга не изменилось.
- **Новых цветов мимо токенов не появилось**, все четыре значения — в `OverlayThemeTokens`.
- **Роль золотого не размыта** — `#FFD600` в этом тикете не используется.
- Блокирующих замечаний нет.

## Итерация 2 — по замечанию пользователя (2026-07-29)

**Замечание:** «ты выбрал оттенки оранжевого, а должно быть brand orange или столько же насыщенные, синий, жёлтый и пр. цвета».

Первый вариант был неправ по существу: я держался собственного NFR «палитра только brand orange + чёрный/серые» и построил ряд `#FF7A1A / #FF9500 / #FFB300`. Это оттенки одного цвета — различимость пунктов от такого ряда почти не выросла. NFR был **моим допущением**, а не требованием пользователя, и решением D-6 он отменён для этих двух меню.

**Новый набор** — разные насыщенные цвета из системной палитры iOS (весь UI построен на iOS-языке, и эти оттенки заведомо читаются и на чистом чёрном фоне, и на светлом):

| | Сортировка | Категории |
|---|---|---|
| 1 | Рейтинг — `AccentOrange` `#E85002` (бренд) | Anime — `AccentOrange` |
| 2 | Эпизоды — `AccentBlue` `#0A84FF` | Movies — `AccentBlue` |
| 3 | По названию — `AccentYellow` `#FFD60A` | Series — `AccentGreen` `#30D158` |
| 4 | По жанрам — `AccentPurple` `#BF5AF2` | — |

Токены переименованы из `SortAccent{Primary…Quaternary}` в `Accent{Orange,Blue,Yellow,Purple,Green}`: прежние имена подразумевали ряд убывающей важности, а теперь это просто разные цвета.

**Побочная выгода:** правка контраста кнопки «Применить» из итерации 1 теперь по-настоящему нужна. С рядом оттенков оранжевого она была почти косметикой, а сейчас акценты расходятся по яркости всерьёз — синий `#0A84FF` получает белый текст, жёлтый `#FFD60A` чёрный. Сравнение с одним конкретным акцентом здесь сломалось бы гарантированно.

**Замечено и вынесено пользователю:** `AccentYellow` `#FFD60A` визуально того же семейства, что золотой избранного `FavoriteGold` `#FFD600`, и оба встречаются на главном экране. Роли разные, цвета почти одинаковые. Разводить надо один из двух — какой именно, решает пользователь. Зафиксировано в KDoc токена.
