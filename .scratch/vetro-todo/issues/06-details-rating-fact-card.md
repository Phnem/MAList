# TICKET-06: Рейтинг — мини-карточкой, верхние чипсы убрать

## Status

DONE (визуальное подтверждение — за пользователем)

## Objective

В Details рейтинг показан такой же мини-карточкой, как остальные факты, а дублирующая строка чипсов под названием удалена.

## User or system value

Пункт 7 списка. Одна и та же информация показана дважды подряд.

## Dependencies

Нет — можно начинать сразу.

## Scope

- `ui/details/DetailsScreen.kt` — строка чипсов под названием.
- `ui/details/DetailsFactCards.kt` — добавление карточки рейтинга.

Образец внешнего вида — существующие мини-карточки (СТАТУС, ЭПИЗОДЫ, ФОРМАТ, РЕЛИЗ, ИСТОЧНИК, СТУДИЯ): скруглённая «пилюля» с круглой иконкой слева, подписью-капсом сверху и значением снизу.

Рейтинг хранится в 10-балльной шкале через `RatingScale` (в БД — INTEGER ×10, легаси <10 — звёзды). Форматировать только через `RatingScale`, вручную не делить.

## Out of scope

Состав и порядок остальных мини-карточек. Секции «Сезоны», кнопки «Смотреть»/«Скачать». Редактирование рейтинга (это AddEdit).

## Acceptance criteria

- [ ] Рейтинг отображается мини-карточкой в общей сетке фактов.
- [ ] Строка чипсов под названием удалена целиком.
- [ ] Ни один факт не потерян: всё, что было в чипсах, либо уже есть среди мини-карточек, либо перенесено.
- [ ] Значение рейтинга форматируется через `RatingScale` (10-балльная шкала).
- [ ] У записи без рейтинга карточка не показывает «0» — либо скрыта, либо «N/A».
- [ ] Сетка не разъезжается при нечётном числе карточек.

## Verification plan

`.\gradlew.bat :app:compileDebugKotlin`. Визуальная проверка — пользователем.

Перед удалением чипсов выписать их состав и сверить с составом мини-карточек — критерий «ни один факт не потерян» проверяется этим списком, а не на глаз.

## TDD classification

NOT_NEEDED — вёрстка. Альтернативная верификация: компиляция + сверка списка фактов.

## Expected architecture impact

Нет.

## Risks

В чипсах может оказаться факт, которого нет среди мини-карточек, — тогда удаление строки потеряет информацию. Отсюда обязательная сверка списком.

## Implementation notes

**Сверка состава — выполнена до удаления**, как требовал план верификации. Верхняя строка содержала ровно три чипса:

| Чипс | Покрыт мини-карточкой? |
|---|---|
| `details?.airedOn` — дата выхода | **Да**, «Релиз». `releaseLabel()` строит значение из `season + seasonYear`, а при их отсутствии откатывается на сам `airedOn`. Оба источника — одно поле, покрытие точное. |
| Рейтинг | **Нет** → перенесён карточкой |
| `anime.episodes` | **Да**, «Эпизоды»/«Главы». Карточка берёт `details?.episodesTotal ?: anime.episodes ?: details?.episodesAired`, то есть покрытие шире, чем у чипса. |

**Правки:**

- `DetailsFactCards.kt`: факт `"rating"` со звездой, плюс приватная `ratingLabel(anime, details)`. Порядок в KDoc обновлён на «Рейтинг, Статус, Эпизоды, Формат, Релиз, Источник, Студия».
- `DetailsScreen.kt`: строка чипсов и предшествующий ей `Spacer(14.dp)` удалены, на месте оставлен комментарий, куда переехал каждый пункт.
- Убраны осиротевшие импорты `RatingScale` и `Icons.Rounded.Star` из `DetailsScreen.kt`.

`ratingLabel` сохраняет прежнее поведение чипса дословно: приоритет у оценки API, развилка `> 10` для 100-балльной шкалы, своя оценка через `RatingScale.format`.

## Deviations

- **Планировалось:** добавить карточку рейтинга.
- **Сделано:** карточка поставлена **первой** в сетке, а не в конец.
- **Причина:** рейтинг — единственный факт, ради сохранения которого строку чипсов вообще разбирали; в конце сетки он потерялся бы.
- **Последствия:** документированный «фиксированный порядок» сместился, KDoc обновлён.
- **Follow-up:** не требуется.

## Review findings

- **Ни один факт не потерян** — подтверждено таблицей выше, а не на глаз. Более того, покрытие по числу серий стало шире: чипс показывался только при `anime.episodes > 0`, карточка учитывает ещё `episodesTotal` и `episodesAired`.
- **«0» не показывается.** `ratingLabel` возвращает null, когда рейтинга нет ни у API, ни у пользователя, и факт просто не попадает в сетку — как и все остальные факты без значения. Ноль здесь означал бы «оценка ноль», а не «оценки нет».
- **`RatingScale` использован** — ручного деления на 10 нет.
- **Сетка при нечётном числе карточек** — `DetailFactGrid` раскладывает строки по два вручную и уже переживал нечётные наборы (студия есть не у всех). Добавление седьмого факта меняет чётность, но не механику. Визуально подтвердить не могу.
- **Потеря оттенка.** У чипса звезда была `Color(0xFFFFCC4D)`, у карточки иконка красится общим для сетки образом. Это осознанно: карточка должна выглядеть «такой же, как остальные» — прямое требование пункта.
- Блокирующих замечаний нет.
