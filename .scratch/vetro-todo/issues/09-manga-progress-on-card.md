## Implementation notes

**Сначала найден существующий механизм для аниме** (как требует Scope): бар на карточке рисует `AiringProgressSection` в `AnimeCard.kt`, данные — `AiringCardInfo` с `CardProgressKind { AIRING, WATCHING }`, решение «какой бар показать» — `rememberCardProgress` в `HomeScreen.kt`. Отдельного индикатора «вышло новое» у карточки нет: у аниме это пуш-стопка `EpisodeUpdateStack` сверху экрана, питаемая `BatchEpisodeCheckUseCase`.

Форма повторена, второй механизм не заведён: добавлен третий вид `CardProgressKind.READING`, поле `AiringCardInfo.newItems`, и тот же `AiringProgressSection` считает главы вместо серий.

**Чистая функция** — `manga/domain/MangaReadingSummary.kt`, 10 тестов:

- `summarizeMangaReading(chapters, progress)` → `MangaReadingSummary(readChapters, totalChapters, newChapters)`.
- Прочитанной считается только глава с липкой отметкой `ChapterReadingProgress.read`; открытая, но не дочитанная — нет.
- Прочитанные считаются **по оглавлению**, а не по отметкам: после смены источника или языка в прогрессе остаются ключи глав, которых в списке нет, и счётчик уехал бы за знаменатель.
- `totalChapters = null`, когда оглавления в кэше нет — карточка тогда печатает «5 ch.» без знаменателя и без бара (требование Failure behavior).
- **Новые главы** = вышедшие (`publishedAt`) позже последнего чтения тайтла и не прочитанные. Просто непрочитанная главой новой не считается — иначе метка горела бы на каждом брошенном на середине тайтле. Пока не прочитано ничего, новых нет: сравнивать не с чем. `publishedAt = 0` («источник даты не отдал») новой не делает.
- `chaptersForLanguage(chapters, preferredLanguage)` вынесена туда же и **используется обеими сторонами** — карточкой и вкладкой «Главы» (`MangaLibraryViewModel.emitChapters` переведён на неё). Иначе вкладка и карточка показывали бы разное число глав.

**Реактивный шов** (карточка в стор не ходит, данные приходят состоянием):

- `MangaChapterCacheStore` получил `flow: StateFlow<Map<String, CachedChapters>>` — поле `cache` стало геттером/сеттером над ним, все существующие пути записи остались прежними.
- `MangaReadingStore.progressFlow(animeIds)` — батч-версия по образцу `EpisodePlaybackStore.furthestEpisodeFlow`: один снимок Preferences на все тайтлы вместо потока на каждый.
- `HomeViewModel.mangaReading: StateFlow<Map<String, MangaReadingSummary>>` — `bindingStore.flow` → `flatMapLatest` → `combine(progressFlow(ids), chapterCache.flow)`. Считается только по тайтлам с подтверждённой привязкой: без неё нет источника, а значит нет и оглавления.

Метка новых глав — оранжевая пилюля «+N» рядом с подписью «Прогресс» (спека: «если такого индикатора нет — точка/бейдж брендовым оранжевым»). Новых цветов не введено, `BrandOrangeBright` уже был.

## Deviations

- **Планировалось:** признак выхода новых глав «по образцу того, как это сделано для серий у аниме».
- **Сделано:** метка считается офлайн, по уже накопленному оглавлению в файловом кэше.
- **Причина:** у манги **нет пайплайна проверки обновлений**. `BatchEpisodeCheckUseCase` первой же строкой фильтрует `mediaType == ANIME`; единственный писатель оглавлений — `MangaLibraryViewModel.loadChapters`, то есть открытие вкладки «Главы». Ровно тот исход, который тикет описал в Risks: «если пайплайна для манги нет, объём вырастет — тогда остановиться и вынести добычу данных отдельным тикетом, а не расширять этот молча».
- **Последствия:** метка «+N» появляется корректно, но узнаёт о новых главах в момент, когда оглавление обновилось — то есть при открытии вкладки «Главы» (или её revalidate по TTL в час). До фонового прохода она не будет опережать пользователя.
- **Follow-up:** `issues/11-manga-chapter-refresh.md` — фоновое обновление оглавлений привязанных тайтлов.

Вторая, мелкая: подпись внизу карточки у манги стала «60 ch.» вместо «60 eps.». Не было в области, но оставлять на одной карточке «12 / 60 ch.» и «60 eps.» — показывать пользователю противоречие; правка в одну строку, аниме не затрагивает.

## Review findings

- **Второй механизм не заведён** — переиспользованы `AiringCardInfo`/`AiringProgressSection`/`rememberCardProgress`, добавлен третий вид прогресса.
- **Оценка «по курам» не поехала на мангу.** `courEstimatedTotal` (ближайшее кратное 12) — приём для сезонов аниме; для `READING` она отключена явно, иначе неизвестное число глав превратилось бы в выдуманное «12».
- **Бар не рисуется без знаменателя.** Раньше знаменатель был всегда (курами), теперь `total` может быть null — бар в этом случае скрыт, остаётся счётчик. Аниме этой ветки не достигает.
- **Карточка не ходит в стор** — `MangaReadingSummary` приходит из `HomeViewModel` состоянием, как и `webLinks`/`airing`/`watched`.
- **Аниме-карточки не изменились:** `episodesUnit` по умолчанию `"eps."`, `newItems` по умолчанию `0`, ветки `AIRING`/`WATCHING` считают ровно как раньше.
- **`layerBackdrop` не задет**, новых цветов нет, `UiStrings` не тронут (подписи «ch.»/«+N» — литералы рядом с уже существующим «eps.»).
- Блокирующих замечаний нет.
