# TICKET-09: Прогресс чтения и новые главы на карточке главного экрана

## Status

PENDING

## Objective

У манги на карточке главного экрана виден прогресс чтения по главам и признак выхода новых глав — по образцу того, как это сделано для серий у аниме.

## User or system value

Пункт 2 списка. Уточнение пользователя на интервью 2026-07-29: речь **не** про ридер (там ползунок страниц и полоса прогресса главы уже есть и работают), а про карточку на главном экране.

Это новая фича, а не починка бага.

## Dependencies

**Блокируется TICKET-05** (общий файл `AnimeCard.kt`).

## Scope

- `ui/home/AnimeCard.kt` — отрисовка прогресса и признака новых глав.
- `manga/data/MangaReadingStore.kt` — источник прогресса чтения по главам.
- источник числа глав и признака «вышли новые» — определить в начале тикета; ориентир — как это устроено для серий у аниме (там уже есть каскад проверки обновлений и `ignored_update`).

Сначала найти и описать существующий механизм для аниме, потом повторить его форму для манги. Не изобретать второй параллельный механизм.

## Out of scope

Ридер (`MangaReaderScreen`, `ReaderDock`) — там всё работает. Пайплайн проверки обновлений для аниме — не переписывать. Рамка/чипс избранного (TICKET-05).

## Acceptance criteria

- [ ] У карточки манги виден прогресс чтения по главам.
- [ ] Виден признак выхода новых глав.
- [ ] Форма повторяет решение для серий у аниме, а не вводит второй непохожий механизм.
- [ ] Если число глав неизвестно, показывается прогресс без знаменателя, а не «X / 0» (Failure behavior из `spec.md`).
- [ ] У аниме-карточек ничего не изменилось.
- [ ] Расчёт доли прочитанного вынесен в чистую функцию и покрыт unit-тестом (0 глав, неизвестное число, все прочитаны, частично).

## Verification plan

`.\gradlew.bat :app:testDebugUnitTest` — тест расчёта доли. `.\gradlew.bat :app:compileDebugKotlin`. Визуальная проверка — пользователем.

## TDD classification

RECOMMENDED — расчёт доли тестируется как чистая функция; отрисовка нет.

## Expected architecture impact

Возможен новый шов между `MangaReadingStore` и моделью состояния карточки. Следить, чтобы карточка не начала сама ходить в стор — данные должны приходить через состояние.

## Risks

Наибольшая неопределённость пакета: источник признака «вышли новые главы» на момент планирования не установлен. Если окажется, что для манги такого пайплайна нет вообще, объём вырастет — тогда остановиться, зафиксировать и вынести добычу данных в отдельный тикет, а не расширять этот молча.
